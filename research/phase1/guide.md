## 范围

本阶段只改变 KV 表示，并测量数值误差、存储、追加写入和读出成本。任务质量实验保持全历史 dense Attention。这里的“检索”指长距离信息检索题；retrieval 路径和页选择器不在本阶段。

| 纳入 | 不纳入 |
|---|---|
| 现成 GQA 模型上的均匀 INT4/INT8、K/V 不对称、layer × K/V 静态位宽 | streaming/retrieval head、路径分派、sink 或窗口驱逐、页评分与 top-k、稀疏访问搜索、RTL |
| 分组完成前的高精度缓冲、近期 INT8/FP16 残留、静态逐 token 标签的布局回放 | INT2、非均匀码本、稀疏异常值支路、GEAR、MiniCache、TurboQuant 完整量化器、GTA/GLA |
| 固定物理块上的打包、反量化、RoPE 和两段矩阵的读出核算 | 新的硬件架构 |

表示的定义见 [configs/quant.md](configs/quant.md)。本阶段按下面的身份使用它们。诊断项不自动成为主候选。

| 表示 | 本阶段身份 |
|---|---|
| Key 离线 per-channel、在线 per-token | 主候选 |
| Key 在线跨 token | 保留位宽与表示交互的数值追加及存储与服务成本的布局对照；不运行真实生成组闭合诊断 |
| 近期高精度残留 | 真实生成与误差来源，以及静态层分配的离线 pre 条件 |

基线是同权重、同位置编码的全量 BF16/FP16 KV，以及均匀 KV8、均匀 KV4。后两者就是主矩阵里「在线 per-token、post-RoPE」那两格，不另开条件。比较一个因素时，其余数值和缓存规则不变。质量实验在短上下文上诊断，在 32K 上做迁移。128K 只进入存储与服务成本，两模型都只做布局计数。

## 执行顺序

`configs/runtime.md` 的准入清单按实测填完之后，再执行：

```text
环境与高精度冒烟
  → 数据清单与 splits/（见 data.md，不运行量化候选）
  → 参考正确性（未通过则停止后续质量结论）
  → 位宽与表示交互（两模型共同的四种 K8V4 进入真实生成与误差来源）
  → 真实生成与误差来源（保留三开发条件各自的已有质量状态）
  → 静态层分配（三格式、三预算的 K 侧分配与 C 全层 KL）
  → 另行冻结 V 与扩样规则
  → 最终候选与扩样
  → 存储与服务成本
  → 整理结果并覆盖回传
```

先 Qwen，再 Llama。同一现象最多追加一组能区分原因的对照。没有主候选通过时，记录失败条件，不自动扩展到 INT2、训练或更多模型。

## 公共实现与统一入口

四个实验继续分别保存执行代码、正式结果和报告。跨实验的持续量化缓存与生成放在
`src/phase1/generation.py`；冻结输入和四问构造放在 `inputs.py`；模型路径与 EOS
放在 `models.py`；高精度生成使用 `runner.generate_bf16`；题目级配对区间统一由
`quality_stats.py` 计算。JSON 读写、原子保存与校验共用 `kvstudy.artifacts`。
`results.py` 负责唯一实体目录、参考视图和完整审核回执，`reuse.py` 负责测量身份判定；
`execution.py` 维护
实际源码发布。实验入口只安排自己的对照，不再维护第二套缓存或生成实现。

阶段运行入口为 `python -m phase1.entry`，默认只读盘点。先用
`plan --experiment <实验名>` 查看已有结果与缺样，再显式执行
`run --experiment <实验名> --commit <实际基准提交>`。真实生成的单个缺测条件另指定
`--task <任务> --condition <格式>`。已有表示交互结果先用其 `--summarize-only`
审核和汇总，不因公共代码迁移重新捕获或重跑主矩阵。静态分配的旧 `select_final`
与 `expand` 命令仅作为当前判定和累计测量的兼容入口。

已完成的四个实验通过只读审核后，在 `source_index.json/reuse_review` 记录正式实体、
模型清单、冻结输入、配置及计算实现的核验依据。`status` 给出四包复用状态；
`plan` 与 `run` 均使用同一目录和回执。回执仍匹配时，已完成包的 `run` 直接复用，
不加载模型、不重写选择和成本结果。依赖有变化时转为 `review`，先审核影响范围。
静态质量计划显示最终各任务的实际已测数量和停止原因，不再把首轮数量当作缺测目标。

| 共用证据 | 唯一维护位置 | 复用方式 |

| BF16、KV8 扩样 | 静态分配的 `reference_expansion/` | 仅保存新增行，在内存合成请求前缀并校验原参考 |

`research/.runtime/phase1-execution/current.json`。也可从已同步且核对一致的服务器
维护树用 `phase1.entry publish` 发布。运行环境按
[服务器说明](../../docs/server-access.md#阶段代码发布与恢复) 选择当前快照，统一入口

来源缺失先核查；不同输入、数值实现或量化条件不能合并。同一参考的首轮只保留

## 写代码时要遵守的约束

环境与高精度冒烟、参考正确性都用这一组约束。存储与服务成本实验把 pre-RoPE 的读时旋转计入成本。

| 约束 | 要求 |
|---|---|
| 全序列词表 logits | Prefill 不物化全部位置的词表 logits。使用 `num_logits_to_keep=1` 或只保留末位。下文的 logit 指送入 softmax 的注意力分数，不是词表 logit。 |
| 注意力路径 | decode 的 score、softmax、累加和反量化目的类型见 data.md。位宽与表示交互的层内误差走同一条路径。 |
| 非方形因果掩码 | query 长度为 1 时，`is_causal=True` 会套用错误掩码。使用 `is_causal=False` 或显式掩码，使单 token 看见全部有效历史。 |
| pre-RoPE | 从旋转前直接取 Key，不做逆旋转。decode 时对历史 Key 重新施加 RoPE。 |
| 长输入中间量 | 不保存完整注意力矩阵和全部位置的词表 logits。轨迹按层保存预登记位置与统计量。 |

## 环境与高精度冒烟

按 [configs/runtime.md](configs/runtime.md) 建立环境，核对模型清单，并在两款模型上做短输入、4K、32K 的高精度冒烟。冒烟代码满足上一节约束。

记录：GPU、显存、BF16 是否可用、prefill 与单步 decode 的时延和峰值显存。峰值含权重、激活和工作区。32K 不可达时记下最大可达长度，不改协议。

通过：两模型短输入冒烟成功，32K 成功或已记录不可达原因，并且 runtime.md 的准入清单已按实测填写。一次性结果先审核，准入事实与来源写入 `configs/runtime.md` 后，清理临时代码、输出与独立报告。

## 参考正确性

排除实现假象。未通过则不做位宽与表示交互–存储与服务成本的质量结论。在合成边界值和少量真实 KV 上核对：

| 检查 | 通过标准 |
|---|---|

## 位宽与表示交互

每格所有层用同一配置。每层以高精度轨迹的隐藏状态为输入，单独计算本层误差，误差不向后传播。下表没有列出的项用 quant.md 的默认数值。主矩阵里的 Value，以及 Key 的在线 per-token 一档，都用该默认，包括 $G_c$ 和参数格式。评估题、两折、离线 scale 的拟合折和 query 位置见 data.md。

| 因素 | 取值 |
|---|---|
| Key | 离线 per-channel；在线 per-token |
| RoPE | pre-RoPE；post-RoPE |
| 位宽 | KV8、K8V4、K4V8、KV4 |

每模型主矩阵 16 个条件。pre-RoPE 与 post-RoPE 用同一批 C 数据分别校准。

主矩阵保留注意力输出相对平方误差 $\|\Delta o\|^2/\|o\|^2$、无效组和容量。$\|o\|^2=0$ 的层单独计数，不进入平均。每题先平均有效层，再对两折等权汇总。无效组按 quality.md 处理。补充归因统一使用下面的配对指标，停止维护旧的重建尾部、正态形状摘要、经验各向同性方差预测和全网 next-token KL 支线。

每个模型另加一格 Value 分组诊断。它不进入主矩阵，也不占追加名额。这一格与主矩阵中「KV4、Key 离线 per-channel、pre-RoPE」配对，只把 Value 改为离线 per-channel，校准折与 Key 相同，其余用 quant.md 默认。它只记录注意力输出相对误差、无效组和容量，不补重建、尾部、饱和率、分数或概率的误差链。它用于检查 Value 分组，不进入当前真实生成候选集。

### 配对归因的测量与判读

配对传播诊断的参数只在 [configs/representation_diagnostics.json](configs/representation_diagnostics.json) 登记。它只增加观测，不改冻结样本、量化规则和主矩阵；诊断补测本身不改变候选。当前候选范围的调整另按下文执行。修改观测配置时直接更新该文件，并重测受影响的诊断；结果中的测量格式标识用于区分实际保存的指标。两模型已完成全部四组配对传播测量，具体结果和审核记录见位宽与表示交互的统一结果与报告。后续新增指标仍须先明确标为待测。

四组 Key 方式 × RoPE 条件分别配对。K8、K4、V8、V4 从同一高精度输入直接量化；不把 K8 再量化到 K4。Q、首个生成 token、历史位置和离线参数拟合折固定。记 $p_8=\operatorname{softmax}(s_8)$、$p_4=\operatorname{softmax}(s_4)$、$\delta s=s_4-s_8$，输出 $o_{88}=V_8^\top p_8$、$o_{48}=V_8^\top p_4$、$o_{84}=V_4^\top p_8$；$o_{\rm HF}$ 是同轨迹高精度参考。指标无需假设残差为高斯或独立噪声。

| 要回答的问题 | 必测量 | 判读方式 |
|---|---|---|
| K 降位宽是否比 V 更影响输出 | $D_K=\|o_{48}-o_{88}\|^2/\|o_{\rm HF}\|^2$、$D_V=\|o_{84}-o_{88}\|^2/\|o_{\rm HF}\|^2$；逐题 $D_K-D_V$、正值题数、均值的配对 bootstrap 95% 区间 | 差值区间是否高于零、方向是否跨题/表示/模型一致；不凭单个总体均值外推 |
| 注意力权重改变多少 | $W=\sum_i p_{8,i}(\delta s_i-\sum_jp_{8,j}\delta s_j)^2$；$D_{\rm KL}(p_8\|p_4)$ | 同条件配对比较两折等权均值，检查 KL 与 $W/2$ 的偏离，不设通用 KL 合格线 |
| 输出变化能否由一阶传播解释 | $\widehat{\delta o}_K=\sum_i p_{8,i}(v_{8,i}-o_{88})\delta s_i$；预测与实测增量的相对残差、余弦 | 残差相对实际 K 增量小、余弦接近 1 支持局部一阶解释；逐层核对偏离的位置与贡献，零向量用 null 和标记，不塞入极小分母 |

概率指标在每个 query head 上计算；输出指标先对整层所有 head 求总能量再归一化。头和层都是同题的重复测量，置信区间只在题目级、两折内重采样，条件于已拟合的互补折参数，不包含重新拟合校准参数的波动。

保留输出误差闭合检查：令 $b=o_{88}-o_{\rm HF}$，则 $E_{48}-E_{84}=D_K-D_V+2b^\top[(o_{48}-o_{88})-(o_{84}-o_{88})]/\|o_{\rm HF}\|^2$。报告交叉项及闭合残差，防止把 KV8 的基线误差误算成 K 或 V 的降位宽增量。主矩阵维持既有 FP32 注意力路径；配对传播诊断使用同一份 FP32 Q、反量化 K/V，以 FP64 计算分数、概率和解释指标，数值口径登记在来源中。早期配对输出诊断保留原数值，不能标成已补测传播指标。

### 新输入上的三个工作点

| 在线 post | K8V4，Key 在线 per-token、post-RoPE，H=0 |
| 离线 pre | K8V4，Key 离线 per-channel、pre-RoPE，H=8、R=128 |

## 静态层分配

本轮检验局部 Key 降位宽代价能否预测完整部署的正确答案损失。基础格式、预算、样本分工、内容位置、配对检查、单层诊断和原生成规则冻结在 [configs/static_layer_allocation.json](configs/static_layer_allocation.json)；完整答案路径、统一重评、关键层保护及配对精度补测冻结在 [configs/static_numerics.json](configs/static_numerics.json)。先完成下列步骤，再审核回传结果并原位更新报告。

1. 修正检索映射。key、正确 value 和干扰键值分别独立随机抽取；值保持八位十六进制后缀，拒绝重复，不以目标 value 加尾缀生成干扰项。沿用原 C 的 2K/4K、四深度和低/高干扰设置。当前静态实验使用 `splits/static_retrieval.json`，完整输入保存在服务器本实验运行目录。旧 `splits/retrieval.json` 及其他实验的历史输入保留原身份，不合并结果。
2. 冻结校准与验证分工。每实验格 fold=0 用于校准排名，fold=1 用于效果验证，各 16 题。离线 Key 参数只使用校准折检索和数学 fold=0 的 32 题，K4/K8 分别从共同源值拟合。配对检查固定八个校准格，仅替换上下文中的目标 value，查询、填料、位置及模型输入 token 总数相同；另在对应旧题面删除目标行，记录 BF16 是否仍给出旧答案。评分记录实测行为，不因失败改样本。
3. 建立答案内容位置。用 tokenizer 的实际字符跨度确定与 `val-` 后十六进制内容相交的 token，跨边界 token 整体计入；保存完整目标 token 序列、跨度、内容索引和产生该预测的 query 位置。每步先测量当前目标 token，再在下一步输入它。内容损失为题内目标 NLL 均值，再对题目等权平均；首个内容位置单列。正确 token 差距是正确 logit 减最强错误候选，不用普通 top-1/top-2 差距。
4. 第一项实验在共同 BF16 正确前缀轨迹上，固定 query、层输入和同一份 V4，计算 K4V4−K8V4 输出的共同参考相对平方变化。先平均有效 KV query 组，再平均题内内容位置，最后平均校准题；保存 K8V4/K4V4 参考误差、K4 重建误差和首内容位置。pre 的重建口径仍为旋转后主存、近期副本替换前。三种格式分别排名，全部分配仅使用校准折的检索排名，并列按层号升序。
5. 由校准排名冻结敏感度、重建、反向及三个固定随机策略，三个预算、仅 K 侧选择、全部 V4；随机排列在预算间嵌套，同模型各格式共用。逐格式、预算核对 INT8 数量与完整成本，相同配置复用测量。验证集不参与位宽表生成。
6. 第二项实验在全部 16 道验证题上计算内容 NLL、正确 token 差距、相对 BF16 的内容词表 KL 和首内容 NLL；每方案读取相同正确 token，但独立维护持续量化缓存。BF16、既定 KV8、同格式全层 K8V4 和 KV4 端点参加同输入比较。保存敏感度与三个随机、重建、反向的逐题配对差异，以及相对同格式 K8V4 的变化和预算趋势。均值大小作为描述，可靠胜负按第 12 步判断，全部预算和负结果保留。
7. 单层机制诊断先测 Llama 在线 post、H=0：B 为全层 K8V4，A_l 仅第 l 层 K4，其余不变。逐题、逐内容位置保存 Delta NLL、KL(B||A_l) 以及相对 BF16 的 KL。校准局部排名与单层完整影响比较；验证题还在 B 的实际状态上重算局部探针，以检查背景差异。排序不一致不直接写成下游放大强度的结论。
8. 保存单层与该格式全部预算策略的 FP32 输出 logits，在相同正确前缀上构造 z_add=z_B+sum_l(z_A_l-z_B)。分别报告实际组合与叠加分布的 KL、正确内容 NLL 差值及消除词表共同平移后的 logit 残差。单层 KL 求和偏差仅作为指标非线性诊断，不直接解释为层间交互；叠加 logits 也偏离实际组合时，再据实讨论超出线性叠加的证据。
9. 统一重评已有自由生成文本：去首尾空白，只接受完整小写 `val-xxxxxxxx` 或裸八位十六进制值，并精确匹配目标值。内容正确率、完整形式合规率和原严格答案正确率分别保留；不从解释或多答案中抽取后缀。八组映射控制同步重评，不改变题面或原预测。本轮不设临时 NLL/KL 质量合格阈值，不自动选出 V 保质预算。
10. 三格式的全部原方案补齐前缀、分隔符、内容和规范终止 token 的正确路径。保存题内最小正确领先量、其位置与竞争 token，另存首次非正位置。自由生成使用相同缓存与无额外 logits 处理的 argmax；严格正路径逐步与自由生成重合，非正位置的替代文本按第 9 步独立评分。
11. 每模型每格式只用原校准 S 选出最高两层并固定保护为 K8，其余层过滤原三个随机排列，再按原三档预算取前 r 层为 K4。位宽表在验证前冻结，所有对照满足相同 K8 数量与完整成本；高精度预算和近期副本保持原规则。
12. 配对数值诊断先聚焦无残留在线 post。两模型重测三档计算条件的 B、原预算组合及保护随机对照；Llama 全部 32 个单层，Qwen 两个校准关键层一并测量。条件依次为当前实现、实际 FP32 输出头、再加入 FP32 decode 残差保存和加法。固定同一 BF16 prefill 源值、正确前缀、参数及位宽表，明确投影和 RoPE 的 BF16 边界，关闭 TF32 与 autocast。每题每条件先两次重复，任一完整 logits 不一致则该题该条件的所有诊断方案扩到六次。重复性和确定性舍入差异分别记录。
13. 题目为重采样单位，对每题各精度/重复下的配对差值取最小/最大实测包络，再用冻结种子与次数计算均值的 95% 包络区间。整个区间严格为负或正时才分别记可靠较低或较高，其余记未分辨差异；实测包络不是通用误差上界。未做完整精度包络的 pre 格式保留配对描述和内容失败，不据微小均值声称数值可靠胜负。
14. 单层与组合比较量化增量 delta z=z_A-z_B。分别报告两半验证题的排名一致性、去共同平移后的叠加绝对 RMS 残差与相对能量比、S 对可靠单层效应的相关。前两项改善不代替第三项；可靠效应不足时停止解释层排序，登记分配信号不足。已有内容正确率、首次生成分歧与明显损失增加另作任务影响判断。

执行入口：先 `python -m experiments.static_layer_allocation.code.content_data --commit <实际发布提交>` 冻结输入，再先 Qwen 后 Llama 执行 `python -m experiments.static_layer_allocation.code.content <模型> --commit <实际发布提交>`。逐题进度与大型 logits 留在服务器 `research/.runtime/static-key-content/`；小型正式记录整理回传至该实验 `results/`，审核通过后作图和写报告。报告继续使用实验目的、实验结果与结论、总结三个二级标题。

已完成的基础内容结果复用原始字节。本轮先 Qwen 后 Llama 运行 `python -m experiments.static_layer_allocation.code.numerics --model <模型> --commit <实际发布提交>`，逐题恢复、固定源值和大型 logits 保存在服务器 `research/.runtime/static-key-numerics/`。补测审核后将原结果与新增正式记录一起整理回传，统一更新同一报告。

## 最终候选与扩样

C 测量结束，保留已有排名、单层代价、预算比较、保护层、完整路径及数值诊断。
收尾只检验已有静态配置在独立真实生成任务上的质量和完整成本，不增加 C 指标、
模型、保护层搜索或精度干预，也不以优于随机策略作为 V 目标。

1. 候选及层表由 static_layer_allocation.json 的 v_plan 唯一指定：Qwen 在线 post
   半层混合，Llama 在线 pre 全层 KV4 和半层混合。层名单必须与原校准冻结配置逐项
   一致，不根据 C 验证或 V 得分重新挑层。同输入 BF16、既定在线 post KV8、候选
   同格式 K8V4 为参考；本轮不新增随机、重建、反向或保护随机的 V 测量。
2. 沿用阶段正式 BF16 权重及激活、共享高精度 prefill 来源和 FP32 注意力 decode。
   各配置持续更新自己的缓存，使用既定贪心、模板、EOS、输出预算与评分。
   先逐份核对设备、软件、数值源码、模型与输入身份、全文和分词、缓存格式、预算、
   停止与评分，登记 reference_reuse.json。新增候选优先沿用已有合格参考的执行条件，
   仅明确的输入、数值实现或执行条件不匹配触发受影响参考补测；来源字段缺失先查证。
   新增候选先取得当前设备的 32K 输入与完整 1024-token 预算运行准入。
3. 质量首轮覆盖 GSM8K、独立数字 32K 检索、32K 单问多证据问答和四问联答。
   初始数量、统计单位、基线下限和输出预算由 v_plan 与对应任务配置确定。
   三套候选均完成四单元首轮。四问联答只由 BF16 长度决定共同配对子集，候选提前
   结束、缺答案和触及上限仍记分；单问与四问不合并统计。
4. 输入扩样先冻结。检索按当前独立七位数字协议生成原扩样池，不混入旧全文；
   四问保留原请求，每四道扩样题按既定顺序追加请求，身份、种子和材料布局不变。
   完成输入依赖、候选层表和参考复用核对后，才将 v_plan 标为已冻结。
5. 质量判定和扩样按 quality.md，两个参考均参与 2 分下降判断。仅扩仍有最终候选
   价值且证据不足的单元，按预定档位累计，前缀全部复用。BF16、KV8 仅追加缺样；
   K8V4 保留已有首轮样本，降低 Key 位宽前的比较注明其实际共同样本范围。
   必要任务淘汰后停止该候选最终资格扩样；上限仍不确定、基线缺口均据实收尾。
   Llama 优先全层 KV4，其全部单元保留后停止混合备选，不将候选收敛写为淘汰。
   KV4 淘汰或达上限仍不确定时，再让混合备选完成必要扩样，不新增替代格式。
6. 当所有仍有候选价值的配置取得保留、淘汰、上限证据不足或基线缺口状态时结束。
   更新已有成本实现，固定比较 KV8、同格式 K8V4、混合与同格式 KV4，长度、物理块
   及连续 decode 计数由 v_plan.cost 指定。容量、读写与服务模型分开记录；128K
   只计布局。审核通过后原位更新静态层分配报告及存储与服务成本报告，保留负结果。

核验完整输出、评分、输入、区间和停止，成本由 `storage_service_cost/code/review.py`

小型候选结果归入静态包的 `results/final_quality/`，必要参考的新增样本归入
`results/reference_expansion/`，判断归入 `results/expanded_quality/`；已有首轮参考继续
使用真实生成包的唯一实体，不在静态包另存副本。完整输入
和预测留在服务器 `research/.runtime/static-final/`；来源索引记录实际源码和设备。

## 存储与服务成本

本实验回答完整驻留和读写需求、字节收益转为时间收益的实现条件，以及结合独立质量
后值得交付的格式。复用已审核的 73 个布局工作点、256 步有效读写、prefill 转换、
操作量和带宽下界；核对模型形状、实际层表、参数、RoPE、残留及计量区间。仅在这些
条件或计数实现改变时重算受影响部分。质量与停止理由直接引用静态分配最终选择。

| 轴 | 取值 |
|---|---|
| 长度 | 4K、32K、128K（128K 只做布局计数，无质量结论） |
| Batch | B = 1 主比较；B = 4 沿用既定 Llama、32K、物理块 64、在线 post-RoPE K8V4 |
| 物理块 | 32、64、128 token |

固定对照为既定在线 post KV8、候选同格式 K8V4、半层混合和同格式 KV4。均为在线
per-token、H=0；逐层位宽读实际冻结名单。原参数组织、逐 token 标签及跨 token 布局
的共用计数实现保留，本轮不追加这些扫描。没有实测带宽时，用 0.1、1、3.35 TB/s
三档假设。接口、缓冲、操作和资源假设统一冻结于
[configs/storage_service.json](configs/storage_service.json)，不将存储对齐当作事务规则。

1. 校验并复用既有结果，单列有效 K/V 载荷读、参数读和追加写入。
2. 计算假设接口的尾部浪费、读改写、合并缓冲与刷新；检查尾块、跨块追加、请求结束
   和恢复边界。当前 token 采用存储参数还原后在片上参与注意力，避免重复片外回读。
   B=4 同时报告整批每步和每生成 token；prefill 转换单列。
3. 补齐解包、参数处理、反量化、追加量化、旋转、QK、softmax、AV 与片上访问。
   区分普通乘加和 FMA，单列三角参数及中间量容量。逐层依次执行，以有限流水递推
   保留填充、排空及 softmax 依赖；共享资源不能假定独立重叠。
4. 同格式比较使用额外开销之差。可加模型要求该差小于字节节省除以共同带宽；流式
   模型按阶段递推。吞吐未知时交付实现门槛，不填入推测加速。Llama 同格式 pre 的
   历史旋转是共同成本；与 post KV8 比较才计其差额。
5. 只有具备完整真实打包读出实现且需要实测延迟结论时，才测 32K、B=1、块 64；
   必要时补 4K。固定平台和数值路径，预热重复，报告波动并定位模型偏差。浮点缓存
   质量路径不能充当测量。缺适用实现时交付服务模型和吞吐约束，实测留待后续。
6. 审核三本账及边界、合并分任务质量状态与样本范围，再原位更新报告。没有排序
   翻转或没有覆盖全部任务的保留候选也可收尾。

结果写入 `experiments/storage_service_cost/results/`：容量与传输前沿、服务时间模型，以及下一阶段要遵守的格式约束。约束表至少记下：

- 主存载荷、scale 与浮点偏移、对齐、残留及标签的完整驻留分量；
- prefill 一次性转换、连续 decode 的 K/V 读取与追加写入；
- pre-RoPE 读时旋转操作数，以及共享、K/V 等分带宽下界；
- 层混合相对同格式 K8V4 的节省和相对 KV4 的额外成本；
- 实际质量状态、失败条件，以及服务模型尚需代入的计算吞吐。

128K 两模型都只做布局计数，不运行前向。Qwen 的配置窗口是 32K，本阶段也不扩窗。没有可靠能量依据时，只记访问和操作次数。

## 停止

| 条件 | 行动 |
|---|---|
| 参考正确性不正确 | 停止候选比较，先修实现 |
| 显存不足 | 调整临时内存组织或换具备准入的设备；保留冻结输入、样本和完整输出预算 |
| 高精度基线不足 | 核查输入、评分与实现；仍不足则登记基线缺口 |
| 区间跨越容差 | 最终候选按 quality.md 扩样；仍跨越则写证据不足 |
| 低位宽全部失败 | 保留 KV8 与高精度的结论和失败边界 |
| 出现新机制线索 | 写入该实验的结果；不扩大本阶段要完成的实验 |

## 结束时留下什么

本轮候选及扩样按已冻结的 v_plan 执行，保留、淘汰、上限证据不足和基线缺口均可
作为收尾结果。四项研究问题的证据、分项质量和失败记录留在对应的 `results/` 目录，
并能追到实际执行来源和 `configs/`。

每个候选的结果至少登记：模型与 prefill/decode 协议；K/V 位宽、轴、$G_t$/$G_c$、scale 来源与格式、舍入与 RoPE；全网或 layer × K/V 分配及其校准来源；追加、未满组、尾块和残留副本；分任务质量、短生成、长解码和检索各自的真实生成与误差来源类别、按 KV head 汇总的检索误差，以及三本账；存储与服务成本约束表里适用于该候选的行；适用条件、失败条件和硬件假设。审核通过后，再按这些结果写报告。

当前结果整理完成后，统一使用 `python -m phase1.entry review --experiment all` 复查。
历史 `python -m phase1.review_results --commit <补测执行提交>` 命令兼容转入同一只读
审核；原字段核对接口仍供输入与残留审核共用，不再调用已退出的旧静态选择、
扩样替换与成本重算链。格式与单位见 [configs/results.md](configs/results.md)。
