## 范围

本阶段只改变 KV 表示，并测量数值误差、存储、追加写入和读出成本。任务质量实验保持全历史 dense Attention。这里的“检索”指长距离信息检索题；retrieval 路径和页选择器不在本阶段。

| 纳入 | 不纳入 |
|---|---|
| 现成 GQA 模型上的均匀 INT4/INT8、K/V 不对称、layer × K/V 静态位宽 | streaming/retrieval head、路径分派、sink 或窗口驱逐、页评分与 top-k、稀疏访问搜索、RTL |
| 分组完成前的高精度缓冲、近期 INT8/FP16 残留、静态逐 token 标签的布局回放 | INT2、非均匀码本、稀疏异常值支路、GEAR、MiniCache、TurboQuant 完整量化器、GTA/GLA |
| 固定物理块上的打包、反量化、RoPE 和两段矩阵的读出核算 | 新的硬件架构 |

表示的定义见 [configs/quant.md](configs/quant.md)。本阶段按下面的身份使用它们。诊断项不自动成为主候选。

| 表示 | 本阶段身份 |
|---|---|
| Key 离线 per-channel、在线 per-token | 主候选 |
| Key 在线跨 token | 保留位宽与表示交互的数值追加及存储与服务成本的布局对照；不运行真实生成组闭合诊断 |
| 近期高精度残留 | 真实生成与误差来源，以及静态层分配的离线 pre 条件 |

基线是同权重、同位置编码的全量 BF16/FP16 KV，以及均匀 KV8、均匀 KV4。后两者就是主矩阵里「在线 per-token、post-RoPE」那两格，不另开条件。比较一个因素时，其余数值和缓存规则不变。质量实验在短上下文上诊断，在 32K 上做迁移。128K 只进入存储与服务成本，两模型都只做布局计数。

## 要回答的问题

| 问题 | 通过时要留下的证据 |
|---|---|
| 位宽与表示交互：Key 优先升位宽是否依赖量化轴、RoPE 和 scale 来源？ | K8V4 与 K4V8 是否换序；误差出现在重建、注意力分数、概率还是注意力输出。结合两模型的输出误差和容量，确定共同的真实生成候选范围 |

| 静态层分配：V4 固定时能否按 K 降位宽代价减少完整成本并保持较小输出偏差？ | 三格式的逐层 K4V4−K8V4 排名，以及三预算下全层 KL、完整成本和同预算六策略对照 |
| 存储与服务成本：质量合格的低位宽表示，何时真正降低传输和服务时间？ | 名义位宽排序与实际字节、服务时间排序是否不同 |

## 执行顺序

`configs/runtime.md` 的准入清单按实测填完之后，再执行：

```text
环境与高精度冒烟
  → 数据清单与 splits/（见 data.md，不运行量化候选）
  → 参考正确性（未通过则停止后续质量结论）
  → 位宽与表示交互（两模型共同的四种 K8V4 进入真实生成与误差来源）
  → 真实生成与误差来源（保留三开发条件各自的已有质量状态）
  → 静态层分配（三格式、三预算的 K 侧分配与 C 全层 KL）
  → 另行冻结 V 与扩样规则
  → 最终候选与扩样
  → 存储与服务成本
  → 整理结果并覆盖回传
```

先 Qwen，再 Llama。同一现象最多追加一组能区分原因的对照。没有主候选通过时，记录失败条件，不自动扩展到 INT2、训练或更多模型。

## 写代码时要遵守的约束

环境与高精度冒烟、参考正确性都用这一组约束。存储与服务成本实验把 pre-RoPE 的读时旋转计入成本。

| 约束 | 要求 |
|---|---|
| 全序列词表 logits | Prefill 不物化全部位置的词表 logits。使用 `num_logits_to_keep=1` 或只保留末位。下文的 logit 指送入 softmax 的注意力分数，不是词表 logit。 |
| 注意力路径 | decode 的 score、softmax、累加和反量化目的类型见 data.md。位宽与表示交互的层内误差走同一条路径。 |
| 非方形因果掩码 | query 长度为 1 时，`is_causal=True` 会套用错误掩码。使用 `is_causal=False` 或显式掩码，使单 token 看见全部有效历史。 |
| pre-RoPE | 从旋转前直接取 Key，不做逆旋转。decode 时对历史 Key 重新施加 RoPE。 |
| 长输入中间量 | 不保存完整注意力矩阵和全部位置的词表 logits。轨迹按层保存预登记位置与统计量。 |

## 环境与高精度冒烟

按 [configs/runtime.md](configs/runtime.md) 建立环境，核对模型清单，并在两款模型上做短输入、4K、32K 的高精度冒烟。冒烟代码满足上一节约束。

记录：GPU、显存、BF16 是否可用、prefill 与单步 decode 的时延和峰值显存。峰值含权重、激活和工作区。32K 不可达时记下最大可达长度，不改协议。

通过：两模型短输入冒烟成功，32K 成功或已记录不可达原因，并且 runtime.md 的准入清单已按实测填写。一次性结果先审核，准入事实与来源写入 `configs/runtime.md` 后，清理临时代码、输出与独立报告。

## 参考正确性

排除实现假象。未通过则不做位宽与表示交互–存储与服务成本的质量结论。在合成边界值和少量真实 KV 上核对：

| 检查 | 通过标准 |
|---|---|
| 实现约束 | 上一节各条约束成立；pre-RoPE 与 post-RoPE 在同一输入上的对照一致 |
| 往返 | 量化—打包—解包—反量化与手算的小张量一致 |
| 布局 | KV8、KV4、K8V4、K4V8 可按 quant.md 的打包规则计数 |
| 边界 | 常量组、超界、未满组、刚闭合组、整块、尾块、非有限值、scale 下溢、参数溢出都有明确结果 |
| 账本 | 手算结果与 quant.md 的三本账逐项一致 |
| 长度 | 短输入先定位，再抽样 32K 的掩码和 prefill/decode 交界 |

这不算任务质量通过。一次性检查的准入状态、覆盖范围与来源写入 `configs/runtime.md`；没有未解决失败后清理临时代码与结果。需要持续保障的回归用例保留在 `research/tests/`，共享实现保留在 `research/src/kvstudy/` 与阶段公共模块中。

## 位宽与表示交互

每格所有层用同一配置。每层以高精度轨迹的隐藏状态为输入，单独计算本层误差，误差不向后传播。下表没有列出的项用 quant.md 的默认数值。主矩阵里的 Value，以及 Key 的在线 per-token 一档，都用该默认，包括 $G_c$ 和参数格式。评估题、两折、离线 scale 的拟合折和 query 位置见 data.md。

| 因素 | 取值 |
|---|---|
| Key | 离线 per-channel；在线 per-token |
| RoPE | pre-RoPE；post-RoPE |
| 位宽 | KV8、K8V4、K4V8、KV4 |

每模型主矩阵 16 个条件。pre-RoPE 与 post-RoPE 用同一批 C 数据分别校准。

主矩阵保留注意力输出相对平方误差 $\|\Delta o\|^2/\|o\|^2$、无效组和容量。$\|o\|^2=0$ 的层单独计数，不进入平均。每题先平均有效层，再对两折等权汇总。无效组按 quality.md 处理。补充归因统一使用下面的配对指标，停止维护旧的重建尾部、正态形状摘要、经验各向同性方差预测和全网 next-token KL 支线。

每个模型另加一格 Value 分组诊断。它不进入主矩阵，也不占追加名额。这一格与主矩阵中「KV4、Key 离线 per-channel、pre-RoPE」配对，只把 Value 改为离线 per-channel，校准折与 Key 相同，其余用 quant.md 默认。它只记录注意力输出相对误差、无效组和容量，不补重建、尾部、饱和率、分数或概率的误差链。它用于检查 Value 分组，不进入当前真实生成候选集。

### 配对归因的测量与判读

配对传播诊断的参数只在 [configs/representation_diagnostics.json](configs/representation_diagnostics.json) 登记。它只增加观测，不改冻结样本、量化规则和主矩阵；诊断补测本身不改变候选。当前候选范围的调整另按下文执行。修改观测配置时直接更新该文件，并重测受影响的诊断；结果中的测量格式标识用于区分实际保存的指标。两模型已完成全部四组配对传播测量，具体结果和审核记录见位宽与表示交互的统一结果与报告。后续新增指标仍须先明确标为待测。

四组 Key 方式 × RoPE 条件分别配对。K8、K4、V8、V4 从同一高精度输入直接量化；不把 K8 再量化到 K4。Q、首个生成 token、历史位置和离线参数拟合折固定。记 $p_8=\operatorname{softmax}(s_8)$、$p_4=\operatorname{softmax}(s_4)$、$\delta s=s_4-s_8$，输出 $o_{88}=V_8^\top p_8$、$o_{48}=V_8^\top p_4$、$o_{84}=V_4^\top p_8$；$o_{\rm HF}$ 是同轨迹高精度参考。指标无需假设残差为高斯或独立噪声。

| 要回答的问题 | 必测量 | 判读方式 |
|---|---|---|
| K 降位宽是否比 V 更影响输出 | $D_K=\|o_{48}-o_{88}\|^2/\|o_{\rm HF}\|^2$、$D_V=\|o_{84}-o_{88}\|^2/\|o_{\rm HF}\|^2$；逐题 $D_K-D_V$、正值题数、均值的配对 bootstrap 95% 区间 | 差值区间是否高于零、方向是否跨题/表示/模型一致；不凭单个总体均值外推 |
| 注意力权重改变多少 | $W=\sum_i p_{8,i}(\delta s_i-\sum_jp_{8,j}\delta s_j)^2$；$D_{\rm KL}(p_8\|p_4)$ | 同条件配对比较两折等权均值，检查 KL 与 $W/2$ 的偏离，不设通用 KL 合格线 |
| 输出变化能否由一阶传播解释 | $\widehat{\delta o}_K=\sum_i p_{8,i}(v_{8,i}-o_{88})\delta s_i$；预测与实测增量的相对残差、余弦 | 残差相对实际 K 增量小、余弦接近 1 支持局部一阶解释；逐层核对偏离的位置与贡献，零向量用 null 和标记，不塞入极小分母 |

概率指标在每个 query head 上计算；输出指标先对整层所有 head 求总能量再归一化。头和层都是同题的重复测量，置信区间只在题目级、两折内重采样，条件于已拟合的互补折参数，不包含重新拟合校准参数的波动。

保留输出误差闭合检查：令 $b=o_{88}-o_{\rm HF}$，则 $E_{48}-E_{84}=D_K-D_V+2b^\top[(o_{48}-o_{88})-(o_{84}-o_{88})]/\|o_{\rm HF}\|^2$。报告交叉项及闭合残差，防止把 KV8 的基线误差误算成 K 或 V 的降位宽增量。主矩阵维持既有 FP32 注意力路径；配对传播诊断使用同一份 FP32 Q、反量化 K/V，以 FP64 计算分数、概率和解释指标，数值口径登记在来源中。早期配对输出诊断保留原数值，不能标成已补测传播指标。

本轮回答：在 V 固定 INT4 的条件下，能否根据各层 K 降位宽的影响，选择部分层使用
INT4，从而减少完整成本，并保持较小的模型输出偏差？前两项实验分别测量局部代价并
产生逐层排序，再将排序变成完整位宽配置，检验有限预算扫描下的整体效果。
整网 KV4 严重失败作为已知风险保留，部分层使用 K4 的效果由组合实验检验。
局部误差、全层 KL 与真实生成质量分别承担证据角色。

模型、三个开发条件、残留与三个探索预算只在
[configs/static_layer_allocation.json](configs/static_layer_allocation.json) 冻结。
两模型分别研究在线 per-token pre-RoPE、在线 per-token post-RoPE，以及离线
per-channel pre-RoPE。前两项 H=0，离线 pre 使用 H=8、R=128，V 均为在线 per-token INT4。
其他分组、参数、舍入、缓存更新与生成设置沿用阶段配置。三条件独立测量、独立排名、
独立分配；不同格式的层排名不互用。同一模型跨格式使用相同随机层集合。

三种格式都是开发候选，不沿用真实生成与误差来源第 5 步选中的单一格式作为唯一输入。
已有质量状态按格式和残留保留；尚未通过的条件仍可用于研究分配效果，不称为保质起点。
H=8 下各策略共用相同窗口与实现，K8V4/KV4 只指低位宽主存，近期副本另记并计入成本。

### 不同表示下 Key 降位宽的层间代价

在冻结 C 的共同高精度轨迹上，固定 query、该层输入及同一份 V4，分别计算
K8V4、K4V4 的本层注意力输出；误差不向其他层传播。K8、K4 均从同一高精度源值
直接量化，不将 K8 再量化为 K4。离线条件使用对应位宽的全部 C 冻结校准参数。
RoPE 与残留按当前条件一致应用；H=8 的近期 Key 副本从 post-RoPE 高精度值生成，
与现有缓存实现相同，Value 副本也共用。

主要敏感度为

$$
S_\ell=\operatorname{平均}_{i,g}
\frac{\|o_{i,\ell,g}^{K4V4}-o_{i,\ell,g}^{K8V4}\|_2^2}
{\|o_{i,\ell,g}^{\mathrm{ref}}\|_2^2}.
$$

$i$ 为题目，$g$ 为 KV head 对应的 query head 组。分母始终是共同高精度输出，
先平均题内有效组，再等权平均题。零能量组不进入组均值，单独计数；
全部组零能量的题记 null，登记有效题数。无效量化组保留计数及题目，按 quality.md
处理；没有定义的误差不填零，受无效量化影响的层不冻结正式排名。
该量表示 K 降位宽引起的局部变化，不是任务分数下降；变化方向不必然远离高精度参考。

同时保存 K8V4、K4V4 各自相对共同高精度输出的误差，用来检查变化方向，
不另外建立分配规则。重建对照沿用逐 KV head 的 K4 相对高精度 K 的平方重建误差，
再平均 head 和题目，明确它按 K4 张量失真排序。pre 条件沿用旧探针的读时旋转后
post-RoPE 张量口径，与对应 post 条件使用同一测量位置；重建误差在近期副本替换前，
对低位宽主存的全部有效位置计算。不能将旋转前和旋转后误差混在同一比较中。

沿用冻结 C 的数学与检索子集、data.md 的首生成 token query 位置，分别汇总。
分配只使用检索排名，数学排名只检查跨任务一致性，不根据比较结果切换来源。
逐层保存敏感度、K4 重建误差、两项参考误差、无效与零能量计数；输出数学／检索敏感度
排名和检索重建排名，记录固定并列规则下的 Spearman 相关与高敏感层集合重合。
高敏感层集合取层数的一半，并列固定取层号升序。

### 不同预算下的 Key 位宽分配与全层验证

$r$ 为 K 使用 INT4 的层数，其余 $L-r$ 层 K8，全部 V4：

$$
p_{\mathrm{INT8}}=\frac{L-r}{2L}.
$$

使用配置冻结的少量层、四分之一 K 层、一半 K 层三个预算。
一半 K 层对应总 K/V 单位 25% 使用 INT8，是较强压缩的探索点，
不预设为主方案或可行预算。每个模型、格式、预算分别构造六策略：
敏感度最低的 $r$ 层 K4；重建误差最低的 $r$ 层 K4；
敏感度最高的 $r$ 层 K4；以及三个固定种子的随机 K4。
每个随机种子生成一份固定层排列，各预算截取前 $r$ 层。
低误差与高误差均按指标直接排序并按层号打破并列，反向不通过倒转低误差排名处理并列。

全部位宽表在全层测量之前冻结，记录实际 K4 层名单、INT8 单位数、完整配置校验值。
同一格式内不同策略／预算的相同配置只测一次，报告重合；跨格式不因层名单相同而复用。
同格式、同预算核对六策略的 INT8 数量及完整字节，参数、对齐、残留容量、prefill 转换
与 decode 读写分别列出；读出记录残留替代尾部及全读两种界，滑动窗口驻留不变时仍计
新 token 的副本写入，pre-RoPE 读时旋转另记操作量。相同 INT8 比例不表示跨格式成本相同。

BF16 为共同质量和分布参考；既定在线 post-RoPE KV8 为高精度量化参照。
每格式保留同残留的全层 K8V4 起点与全层 KV4 端点。
全层测量仅做共同首 token 后一步 decode，不重跑完整自由生成组合。
已有严重失败继续保留，完整生成不强制重跑；历史在线 post-RoPE KV4 的失败
不能代表其他格式或残留下的 KV4。必要的端点跳过必须登记同输入、同格式、同残留的来源，
不能把 V 自由生成失败当作 C 的端点 KL 数值。

全部层同时应用目标配置，用共同高精度 prefill 的首 token 输入下一步 decode，
候选独立维护全层缓存，测量词表分布

$$
G(a)=\operatorname{平均}_i D_{\mathrm{KL}}(p_i^{\mathrm{BF16}}\|p_i^a).
$$

数学与检索分开报告，主比较仍取检索。全部参照与策略统一使用 FP64 稳定 KL，
通过归一化分布恒等式减少近零相消；注意力数值路径仍沿用 FP32。
对近零结果核查自比较、常数 logit 平移及高精度计算，不把数值负值作为策略收益。

记录各方案相对同格式 K8V4 起点的 KL 差值、增加 K4 层数的变化，以及逐题差值。
差值描述方案变化，不作为可加的单层误差分解。每预算独立判断敏感度策略是否
严格低于全部三个随机、是否低于重建、是否低于反向；结论只登记对应模型、格式、
预算及校准集的方案级证据。检查差异方向、少数大值的贡献，三个预算全部保留。
没有预先验证的通用 KL 合格线，不能仅凭 KL 宣布预算保质，也不临时设阈值。

若进入 V 前需筛除明显失效预算，先在配置中冻结 C 真实生成检查的条件与样本、
高精度基线准入、评分、严重失效停止条件及预算保留规则。该检查属于开发筛选。
当前 generation_screen 未冻结，先完成预算—KL 比较，不自动选择质量合格预算。

原“K4、V 高精度”探针不能代替新指标，旧 p25/p50 的全 K/V 分配也不能代替仅 K 分配。
符合模型、输入、表示、残留、参数和实际代码来源要求的高精度轨迹与校准可以复用；
当前入口重新捕获共同轨迹并计算新输出指标。源题面、实际 token 输入与校准实体校验
随结果保存，旧 Llama 检索探针不与当前完整键输入合并。

预测分布比较，以及明确失败条件和待验证候选。后续进入 V 的格式、预算、策略数量与
扩样规则另行冻结，当前 v_plan 未冻结，原自动 C 门槛→V→扩样→成本链停止于 C 的 KL。
真实生成入口与扩样入口在规则未冻结时拒绝执行。既有 V 与扩样保留其历史意义，
不自动成为新方案的质量证据。

新数字键值检索已具备 BF16 基线；同输入 KV8 与量化候选是否已补齐按正式结果核对，
不得与旧候选输入混配。新方案的候选和扩样计划确定后再更新本节及实现衔接，
不沿用旧 p25/p50 配置或旧“门槛失败则改用重建”的选择。
存储与服务成本当前已有候选仍是历史输入；本轮 C 结果不会自动改写它们。

## 存储与服务成本

在质量候选和必要的失败对照上做有限扫描。测量区间是连续 256 个 decode 步，与按任务停止的质量实验分开。字节、名义位宽、算术强度和带宽下界按 quant.md 计算。

| 轴 | 取值 |
|---|---|
| 长度 | 4K、32K、128K（128K 只做布局计数，无质量结论） |
| Batch | B = 1 必做；B = 4 只做一个代表条件：Llama、32K、物理块 64、真实生成与误差来源选定的表示（全部淘汰时用 KV8） |
| 物理块 | 32、64、128 token |

三组对照：同样元素位宽下比较参数组织；同样精度比例下比较按层连续布局和静态逐 token 标签；比较 KV8、K8V4、K4V8、KV4 的读出代价。标签布局不运行 token 显著性算法。没有实测带宽时，用 0.1、1、3.35 TB/s 三档假设；主结论是名义位宽排序发生翻转的带宽阈值，三档只作示例。

结果写入 `experiments/storage_service_cost/results/`：容量与传输前沿、服务时间模型，以及下一阶段要遵守的格式约束。约束表至少记下：

- pre-RoPE 的读时旋转是否改变 $T_{\mathrm{shared,lb}}$ 与 $T_{\mathrm{split,lb}}$ 的排序；
- 物理块长是不是所用 $G_t$ 的整数倍；未满组以高精度参与 Attention 时，是否已按残留计入三本账；
- K 与 V 分存时，分通道下界是否短于共享带宽下界；
- scale 与浮点偏移在 4K 和 128K 各占传输的比例，名义位宽排序在哪一档带宽假设下翻转；
- 残留区在本工作点上是第二种静态精度，还是可以不用；
- 层混合相对均匀 K8V4 / KV4 的完整字节差，是否大到要按层切换数据通路。

128K 两模型都只做布局计数，不运行前向。Qwen 的配置窗口是 32K，本阶段也不扩窗。没有可靠能量依据时，只记访问和操作次数。

## 停止

| 条件 | 行动 |
|---|---|
| 参考正确性不正确 | 停止候选比较，先修实现 |
| 显存不足 | 减临时张量、分块或轨迹；不缩短上下文，不减少样本 |
| 高精度基线不足 | 记下缺口，修订配置后再比候选 |
| 区间跨越容差 | 最终候选按 quality.md 扩样；仍跨越则写证据不足 |
| 低位宽全部失败 | 保留 KV8 与高精度的结论和失败边界 |
| 出现新机制线索 | 写入该实验的结果；不扩大本阶段要完成的实验 |

## 结束时留下什么

后续最终候选数量按另行冻结的 V 与扩样计划确定，允许负结果。四项研究问题的证据、分项质量和失败记录留在对应的 `results/` 目录，并能追到代码版本和 `configs/`。

每个候选的结果至少登记：模型与 prefill/decode 协议；K/V 位宽、轴、$G_t$/$G_c$、scale 来源与格式、舍入与 RoPE；全网或 layer × K/V 分配及其校准来源；追加、未满组、尾块和残留副本；分任务质量、短生成、长解码和检索各自的真实生成与误差来源类别、按 KV head 汇总的检索误差，以及三本账；存储与服务成本约束表里适用于该候选的行；适用条件、失败条件和硬件假设。审核通过后，再按这些结果写报告。

历史质量结果整理与复核入口为 `src/phase1/review_results.py`。在同一 node8 交互环境中运行 `python -m phase1.review_results --commit <补测执行提交>`，核对冻结输入和全部 C 校准、统一质量字段、归并相同扩样前缀，并在运行目录的隔离副本复算历史选择与成本；新 Key 分配的 C 结果按本轮指标与冻结位宽表独立审核，不沿用历史自动选择。已规范化结果再次运行时只审核，不再次替换或改写历史来源。格式与单位见 [configs/results.md](configs/results.md)。
