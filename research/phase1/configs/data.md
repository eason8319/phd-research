# 第一阶段数据与生成配置

本文件只冻结生成方式、样本划分、题目评分和基线能力下限。实验顺序见 [../guide.md](../guide.md)。本文件与 guide.md 共同定义当前实验约定。样本 ID、种子和扩样顺序写入 `research/phase1/splits/`。

候选之间怎么取舍见 [quality.md](quality.md)。这里的下限只决定一个任务单元能不能用来做量化保真结论。

## 生成

下列设置对所有质量实验生效。要改其中任何一项，直接更新本文件并单列条件，重跑受影响的对照。

- 贪心解码、单 beam、`repetition_penalty=1.0`，覆盖模型文件里的采样默认值。
- EOS：Llama `{128001, 128008, 128009}`；Qwen 为 `<|im_end|>` 与 `<|endoftext|>` 的 tokenizer ID。遇任一 EOS 即停。
- 短数学题与长问答 `max_new_tokens=1024`；检索题 `max_new_tokens=128`。
- 32K 指输入加输出合计 ≤ 32,768，并计入 chat template。长问答主比较的输入约 30K–31K，检索输入约 31K。长解码诊断的输入留出 1024 token 的生成预算，仍用长问答的 `max_new_tokens=1024`。逐样本记录实际长度。1K = 1024 token。
- Llama-3.1 的 chat template 固定 `date_string=26 Jul 2024`，不用当天日期。两模型都使用各自模板的默认 system prompt：Qwen 注入其默认身份句，Llama 注入 Cutting Knowledge Date 段。实际拼进输入的前缀写入该次运行的输入记录。
- 本阶段不给 Qwen 扩窗。可用窗口以 runtime.md 的配置窗口为准。
- prefill 用高精度计算，再构建目标 KV；所有条件共用模型的标准 SDPA。decode 读取该表示并量化新增 KV。量化 prefill 若要做，单列条件。
- decode 的注意力路径对高精度基线和全部候选相同。KV 反量化直接到 FP32，不经过 BF16 或 FP16。score、softmax 和注意力输出的累加用 FP32。权重和激活仍用 runtime.md 的 BF16；若环境与高精度冒烟把两模型统一改为 FP16，权重和激活跟随，注意力路径仍是 FP32。

## 划分

C 只用于 scale、层排序和配置搜索。V 只用于本阶段的迁移和候选取舍，结论仍是开发证据。T 本阶段不使用；ID 与种子独立，留给后续正式测试。

| 数据组 | 数量 | 来源 |
|---|---:|---|
| C 短困难生成 | 64 | GSM8K train |
| C 检索探针 | 32 | 合成；2K/4K；4 个证据深度 × 2 档干扰 |
| V 短困难生成 | 64 | GSM8K train，与 C、T 不重叠 |
| V 32K 检索 | 64 | 4 深度 × 2 干扰 × 8；种子与 C、T 分离 |
| V 32K 多证据问答 | 64 | HotpotQA distractor，按 RULER 思路改编 |
| 长解码四问联答 | 16 个请求，64 个问题 | 完整 V 顺序，每四题一组；按请求评分 |
| 历史单问长解码诊断 | 8 | 原子集与原结果保留其历史协议 |
| V 扩样池 | 每个 V 单元再加 192 | 与对应 V 单元同源；只供 guide.md 的最终候选与扩样扩样 |
| 四问联答扩样 | 追加 48 个请求 | 原 Hotpot 扩样顺序每四题一组；累计上限见 long_decode.json |
| T | 保留 | 本阶段不使用 |

## 数据来源与 splits/ 的生成

- GSM8K 用 `openai/gsm8k` 的 `main` 配置、train split。HotpotQA 用 `hotpotqa/hotpot_qa` 的 `distractor` 配置、validation split；V、扩样池与 T 都从这里取互不相交的问题 ID，32K 装箱的填充段落取自同一 split 中其他问题的段落，不取 T 问题的支持段落。
- 从 Hugging Face 或其 ModelScope 镜像下载到服务器 `research/.runtime/data/`。实际来源、数据集修订号、split 和逐文件 SHA256 写入 `research/manifests/data/`，与模型清单同样纳入 Git。
- 执行代理在环境与高精度冒烟之后、参考正确性之前一次生成 C、V、扩样池与 T 的问题 ID、两折、种子、扩样顺序、GSM8K 零样本模板、检索题面模板、HotpotQA 装箱规则、长解码问法和解释性轨迹子集，写入 `splits/` 并回传本地。这一步只用 tokenizer 计数长度，不运行任何模型前向。之后 `splits/` 以本地为准，不再改写。
- 合成题与 32K 装箱由种子和 `splits/` 的规则确定性重建。全文留在服务器，`splits/` 只写 ID、种子、模板、规则和全文的 SHA256。

- GSM8K 用 `splits/templates.json` 中的固定零样本模板。末行给出具体数字示例 `#### 42`，不写可能被照抄的 `<number>` 占位符。答案示例修正只改这一题面；C、V、扩样池与 T 的题目 ID 和折不变。官方 test 留给后续正式测试。
- HotpotQA 的主问法和长解码问法要求最后一行以 `Final answer:` 开头，后接实际答案，不出现可能被照抄的 `<answer>` 占位符。占位符修正只改这两种问法；V、扩样池与 T 的问题 ID 和原有装箱材料不变，全文长度、支持文档位置和校验值重新计算。
- 检索深度约 10%、35%、65%、90%，按 token 位置除以输入长度取最近的位置。目标键在材料中仅对应一个值；干扰记录使用同一格式但完整键不同，题面要求完整键匹配。普通背景是无关句子。完整键匹配要求修正此前干扰记录复用目标完整键造成的歧义，C、V、扩样池与 T 的题目 ID、种子及折不变。
- 当前 V 32K 检索使用 `configs/retrieval.json` 冻结的 RULER 单目标改编构造。
  保留原 64 题 ID、种子、四个深度和两档干扰；同一种子先独立无放回抽取七位数字键，
  再抽取七位数字值。低／高档为 1／8 条干扰，重复无关句按 tokenizer 装到不超过
  31,744 token，模型 chat template 后追加固定答案前缀。两模型键值相同，背景长度分别适配。
  模板、插入规则、随机数规则、RULER 源码校验值和评分只在该 JSON 登记；
  新输入逐题记录在 `splits/retrieval_ruler.json`，正文只留服务器。
  这不是 RULER 原版全套评测。原 `splits/retrieval.json` 及旧 BF16 结果保留其历史协议，
  C 校准与 T 保持原协议；静态收尾的扩样池按 retrieval.json 的 expansion 冻结
  同一独立数字键值构造，保留原扩样身份、种子和分层顺序，全文另存。
- C 分成两折，数学与检索都分层，写入 `splits/`。位宽与表示交互的离线 scale 在互补折上拟合，误差在留出折上计算，两折都做。评估 query 是高精度 prefill 之后、贪心得到的第一个生成 token；各表示共用这个 token。
- 长问答保留支持材料与干扰文档，记录两份支持文档的位置，证据间隔 ≥ 8K token。主比较要求简短解释加单独最终答案。这是项目改编，得分不写成 RULER 原版。32K 困难生成必须使用远距离材料，不用把短题填充到 32K。
- 当前长解码用 `configs/long_decode.json` 冻结的四问联答：完整 V 64 题按原顺序每四题组成
  一次请求，共 16 次请求；材料后列四个问题，最后放输出要求。每题写 3–5 句证据说明，
  最后输出四行编号短答案。每个证据对间隔至少 8K token，输入与 1024 token 输出预算
  合计不超过 32,768。两模型使用同一分组，按各自 tokenizer 装箱，输入登记在
  `splits/hotpot_four.json`。先平均请求内四题的 F1，再平均请求，独立统计单位为请求；
  标签同行或下一非空行均可抽取，缺失答案计零，不借用另一题标签。全部请求得分与输出长度均保留，不足 256 token 单列，
  后续配对只使用 BF16 达到长度要求的同一请求子集，其请求均值 F1 须 ≥40。
  具体模板、装箱、抽取、准入及请求扩样规则只在该 JSON 登记。原 16 个请求保持
  不变，扩样题按原顺序每四题组成新请求，不重组原请求；最终有效请求数由 BF16
  长度准入实际决定，不从 T 或其他来源补题。本轮先完整重跑 BF16。
  原 8 道单问长解码的问法、输入与失败结果保留，不能将其分数当作新协议的参考。
- HotpotQA 的 V、扩样池与 T 使用不相交的原始问题 ID。样本 ID 与种子按上一节写入 `splits/`。C 的问题 ID、两折划分、GSM8K 零样本模板和 C 的 2K/4K 检索题面未写入时，位宽与表示交互不开始。V 的问题 ID、32K 检索题面、HotpotQA 装箱和长解码问法未写入时，真实生成与误差来源不开始。
- 两模型使用同一问题 ID，按各自 tokenizer 调整干扰长度。同一模型的所有候选输入字节级一致。
- 位宽与表示交互的误差汇总用 C 的全部题，按留出折计算，不用 8+8 代替。预选轨迹是 C 中 8 道数学加 8 道检索，只做按层、按 head 的解释性记录。V 的解释性轨迹子集在运行前冻结，写进 `splits/`，其中须列入 32K 检索题，题量一并写入。按 KV head 的误差统计用 C 的 8 道检索和这些 32K 检索题；只保存预登记 query 位置上的按层、按 KV head 统计量。
- 开跑前检查 C、V、扩样池与 T 的问题 ID、文本重复和生成种子重叠。
  四问联答须覆盖完整 V，每个问题恰好使用一次；历史单问子集保持原 ID。

## 评分与基线能力

| 任务 | 评分 | 高精度基线下限 |
|---|---|---|
| GSM8K | 抽取最终数值，按官方规则做 EM | EM ≥ 50 |
| V 32K 检索 | 按 `retrieval.json` 抽取唯一七位数字值，匹配目标做 EM；整段 EM 仅为格式诊断 | EM ≥ 90 |
| 历史检索与 C 探针 | 预登记目标串规范化后整段 EM；保留原协议含义 | 不复用其分数判定新 V 构造 |
| 长问答 | 抽取最终答案；EM 与 token-F1 | 答案 F1 ≥ 40 |

支持材料移除只作为固定小样本诊断。未达下限时先查模板、长度、评分和实现。仍然不成立则记下缺口：该单元不用于量化保真结论，也不只挑基线答对的题重算主分数。检索和长问答的第一个答案 token 由高精度 prefill 决定，量化 KV 从第一个生成 token 的 query 才开始被读到；报告 EM 或 F1 时写明这一点。
