# 项目范围界限

课题：面向长上下文 Decode 的精度感知 KV Cache 流式 Attention 架构与映射

本文档规定本课题**做什么、不做什么、以什么证据算完成**，作为开题、实验设计与论文贡献组织的范围依据。文献核查、反例分析与有明确停止条件的短期可行性实验可以先行；改变主贡献、增加必交付成果或降低验收要求时，按第 7 节修订范围。

**范围修订：2026-09-21。** 本文区分“核心必做”“有条件扩展”和“范围外”。资源尚未确认的配置必须在正式实验前登记并冻结，不视为已经具备的条件。

---

## 1. 一句话定义

在长上下文自回归 decode 阶段，研究 **KV 精度、页选择粒度与存储传输粒度之间的耦合**，设计支持规则流式访问和预算受限页检索的数字 Attention/KV 引擎，并给出从质量约束到存储布局、计算阵列与调度的映射方法。

核心研究假设是：在任务质量和硬件资源相同的条件下，联合选择 KV 精度、逻辑/物理页组织及数据通路映射，能够降低对齐浪费、选页开销和流水停顿，改善分步优化后直接组合方案的能量–延迟取舍。**该假设及其新颖性均待文献对照和实验验证，不能以“组合了稀疏、量化和硬件”直接认定创新。**

主比较口径是在给定质量与 Attention 延迟预算下，最小化 Attention 引擎及其存储访问的每生成 token 能量；同时报告传输字节、延迟和质量的 Pareto 曲线：

$$
\min_{\pi,\; b,\; \mathcal{M}} \; E_{\mathrm{attn+mem/token}}
\quad \text{s.t.} \quad
\Delta q_{m,t,S} \le \epsilon_{t,S},\;
T_{\mathrm{attn}}(B,S) \le T_{\max}(B,S),\;
\mathrm{Area} \le A_{\max},\;
C_{\mathrm{SRAM}} \le C_{\mathrm{SRAM,max}},\;
C_{\mathrm{offchip}} \le C_{\mathrm{offchip,avail}},\;
f_{\mathrm{clk}} \ge f_{\min}
$$

其中 $\pi$ 为 KV 保留与访问策略，$b$ 为第 2.5 节限定的精度配置，$\mathcal{M}$ 为页布局、tile、bank、PE 与调度的映射；$m,t,S,B$ 分别表示模型、任务、当前上下文长度和活跃序列数。$\Delta q$ 表示相对同配置全量高精度 KV 基线的任务质量下降，具体定义见第 5 节。

片外通道数、突发粒度和可持续带宽是固定硬件输入，带宽竞争与停顿必须进入延迟和能量模型。$C_{\mathrm{offchip,avail}}$ 为扣除同设备权重及其他保留区后的可用容量；不得把未选中但仍保留的 KV 从容量核算中删除。预算数值在第 6 节的配置冻结阶段确定。

## 2. 研究对象边界

### 2.1 阶段

| 项目 | 界定 |
|---|---|
| **在范围内** | Decode（自回归逐 token 生成）阶段的 Attention 与 KV Cache 访问 |
| **仅作接口** | Prefill：规定 KV 格式、位置编码约定、精度标签、页元数据及 Attention mask 兼容性；记录格式转换、元数据构建与传输成本，不优化 prefill 计算本身 |
| **允许的离线准备** | 不更新基础模型权重的校准、KV head 分类、精度选择及有限参数搜索；校准集与最终测试集分离，报告准备成本与是否需要梯度 |
| **不在范围内** | 基础模型训练、微调、蒸馏、量化感知训练；prefill 加速器 |

不得把 prefill 侧准备工作当作零成本。一次性成本与稳定 decode 成本分别报告；需要摊销时注明生成长度。若所选策略要求改变 prefill 的 Attention mask，应在质量参考实现中同步体现，不能仅假设 KV 存储格式相同就具有相同语义。

### 2.2 算子

| 项目 | 界定 |
|---|---|
| **在范围内** | $QK^\top$、online softmax、$AV$，以及 KV 的读、写、量化、反量化、页选择与窗口驱逐 |
| **仅作系统边界** | QKV 投影、输出投影、FFN、LayerNorm、MoE 路由：作为流水线上下游建模其带宽与延迟，不为其设计新计算单元 |
| **不在范围内** | 采样 / 解码策略（beam、speculative decoding 等），除非用来说明 decode 批宽度对 Attention 数据流的影响 |

### 2.3 模型

| 项目 | 界定 |
|---|---|
| **核心必做** | 两款可获得权重的 decoder-only GQA 模型，优先选择两个系列的 7B–14B 级模型；冻结具体 checkpoint、版本、位置编码配置与有效上下文窗口 |
| **有条件扩展** | 70B 级 GQA；MLA 的张量形状、投影/广播与映射分析。均不作为核心验收前提，MLA 不要求新增 RTL 通路 |
| **不在范围内** | 编码器模型（BERT 类）；线性 Attention / SSM / RWKV 等非 KV 驻留架构；多模态编码器；MoE 专家调度 |

### 2.4 上下文、生成长度与批大小

- **核心上下文档位**：$S=32\mathrm{K},64\mathrm{K},128\mathrm{K}$，其中 $1\mathrm{K}=1024$ token；$S$ 为当前可见历史长度，逐步生成时随 KV 追加而变化。
- **核心效率实验**：$B=1$，每个长度档以连续 256 个 decode 步测量稳定性能，记录实际 $S$ 范围。接近窗口上限时缩短 prompt，使输入与生成总长度不超过已验证窗口。额外以 $B=4$ 的 trace/模型评估带宽竞争和调度，不要求新增服务系统。
- **核心质量实验**：按任务协议设置输出长度与停止条件，登记输入、输出及总长度的实际分布；不能为统一效率测量而截断任务答案。
- **有条件扩展**：256K 上下文、较大 batch、长时间连续生成。$1\mathrm{M}$ 级仅作容量与带宽外推，不据此外推任务质量。
- **短上下文**：$S\le4\mathrm{K}$ 可作开销或瓶颈对照，不作优化主目标。Attention 是否主导取决于模型、batch、精度和平台，不使用固定长度阈值作普遍结论。

两款核心模型均须先验证高精度基线在目标长度档上的任务能力。模型系列名称不代表支持全部档位；扩窗方法及其质量影响应单独登记，不开发新的扩窗算法。若核心档位无法成立，按第 7 节修订，不能用无效基线上的小分数差代替保真验证。

### 2.5 精度

| 项目 | 界定 |
|---|---|
| **核心必做** | KV 存储支持 INT4/INT8 两档；允许 K/V 不对称。精度按“layer × 路径类型（streaming/retrieval）× K/V”静态配置，同一配置单元内采用同档精度 |
| **数值实现** | 采用已有量化方法，明确 scale/zero-point、分组、舍入、饱和与位置编码顺序；score、softmax 和累加采用经验证的固定格式，不另立通用低精度算法贡献 |
| **有条件扩展** | INT2、非均匀码本、同路径内不同 KV head 的独立精度、动态 page 精度及运行时重打包 |
| **仅作既定输入** | 权重量化（W4/W8）、激活量化：采用已有方案（如 QServe/AWQ 配置）作为给定条件，不研究其算法 |
| **不在范围内** | 新的通用量化算法、量化感知训练；FFN/投影层的精度设计 |

FP16/BF16 全量 KV 用作质量和算法基线，不自动要求主 RTL 增加完整浮点数据通路。若核心方案需要高精度残留区或回退，须显式纳入格式、容量、数据通路及成本，不能作为免费例外。

GQA 中必须区分 query head 与 KV head。核心方案以 **layer 内的 KV head（及其共享该 KV 的 query head 组）** 为路径分派单位，同组采用一致的保留策略；不得按 query head 数重复计算 KV 压缩收益。页按该共享关系组织，精度标签标识静态配置，decode 期间不动态改变历史页精度。

### 2.6 稀疏与流式

| 项目 | 界定 |
|---|---|
| **核心必做** | 规则流式（sink + 局部窗口）；KV head 组的静态路径分类；一种基于 page min/max 的页选择方法及其逻辑/物理页映射 |
| **有条件扩展** | 低秩 score 等其他选择器、层级访问预算、跨 decode 步复用选择结果；每项扩展分别核算收益和开销 |
| **仅作对照** | H2O 类 token 动态驱逐；不要求为其开发专用 RTL |
| **不在范围内** | 开放式 token 级任意 gather；片上 ANNS / 向量数据库检索；CPU/主机侧卸载与预取的系统策略（InfiniGen 类），只作对照 |

### 2.7 “有界检索”的可执行定义

这里的“有界”指在明确的最大上下文、存储和访问预算下可计算最坏开销，**不表示选页或整个 decode 的复杂度与上下文长度无关**。正式实验前须冻结下列参数或有限搜索集合：

| 项目 | 必须说明 |
|---|---|
| 页组织 | 逻辑页与物理页的 token 数、对应关系、精度分组、突发对齐与尾页处理 |
| 候选扫描 | 每个 query/KV head 组扫描的元数据范围与最大页数；核心默认扫描全部历史候选页，计算和流量随候选数计入 |
| GQA 选择共享 | 明确各 query head 的评分如何形成 KV head 组的读取集合；若取所选页并集，$K_{\max}$ 约束去重后的组级集合，不能把多个 query 的预算分别计作同一份读取 |
| 读取预算 | 每步、每组最多读取的物理页数 $K_{\max}$；强制保留的 sink/局部页是否计入，去重后实际读取字节 |
| 选择器 | min/max 统计的数值格式与更新，评分、top-k、地址重排、队列深度、bank 冲突和最坏服务周期 |
| 更新与回退 | 核心每步重新选页；追加 KV 和元数据更新计入成本。预算不足时记录质量失败；任何增大预算或全量回退均计入开销 |
| 容量 | streaming 组只保留约定窗口；retrieval 组保留可再次选择的历史 KV。未被当前步骤读取的历史页仍计入容量 |

选择数量有限不保证物理地址连续。允许页间非连续访问，但以页为传输单位；报告实际突发利用率和控制成本。组内评分归并、预算截断与广播规则须在软件和 RTL 中一致，并参与质量验证。量化后的页统计需验证其评分误差，不能直接把未量化统计的选择质量用于量化实现。

## 3. 硬件与实现边界

### 3.1 目标平台

| 层次 | 界定 |
|---|---|
| **核心必做** | 数字 ASIC 风格 SystemVerilog RTL、功能/数值验证，以及在已确认工艺库和约束下的面积、功耗估计、时序结果 |
| **核心建模** | 由 RTL 仿真校准的周期或事务级性能模型；片外存储参数有来源，明确校准范围、误差与外推部分 |
| **有条件扩展** | HBM FPGA 原型，用于功能与带宽实测；无需把 ASIC 和 FPGA 两套完整优化设计同时作为核心交付 |
| **不在范围内** | 流片（除非后期有资源，届时另立范围）；模拟/存内计算（CIM）、PIM、光计算等非传统数字实现；GPU kernel 作为主贡献（只作基线） |

综合结果不等同于流片测量。功耗估计须说明活动率、工作负载、工艺角与时钟条件；SRAM 宏、控制逻辑和片外内存能量分别列账，避免遗漏或重复计数。没有布局布线证据时，不声称得到签核时序或芯片实测功耗。

### 3.2 存储层次

- **在范围内**：片上 SRAM 的 bank、端口、容量及元数据缓存；片外存储突发与通道对齐；KV packing、DMA 与流式预取。核心先固定一种片外接口和参数集，其他接口作敏感性分析。
- **仅作参数**：多芯片 / 多卡互连带宽，用于说明扩展性；不设计 NoC 路由协议。
- **不在范围内**：CXL / 解聚内存系统；主机内存与磁盘层的服务策略；多租户调度。

### 3.3 映射的含义

本课题所称“映射”限定为：

1. Layer 内 KV head 组到 **逻辑访问路径**（规则流路径 / 有界检索路径）的分派；双路径不预设必须复制两套计算阵列；
2. 第 2.5 节静态精度配置到 **存储格式与 MAC 配置** 的绑定；
3. 沿 $S$、head、$d_h$ 的 tile 划分及其到 **SRAM bank / HBM channel / PE 阵列** 的绑定；
4. 引擎内部选页、搬运、反量化与计算的流水调度；相邻线性层仅作接口和系统延迟建模，重叠须满足数据依赖且计入缓冲与资源竞争；
5. 在固定硬件模板和有限参数集合中进行约束搜索；报告搜索预算、准备成本、失败配置和可行解，不要求证明全局最优。

不包括：通用编译器（MLIR 等）基础设施建设；面向 GPU 的 kernel 自动调优；训练图编译。

## 4. 交付物边界

核心交付包括刻画、架构和映射三个部分，以同一组模型、数值格式和资源配置串联验证。第 2、3 节的扩展项不构成完成前提。

### 4.1 刻画（对应 $\pi$ 与 $b$ 的可行域）

- 两款核心模型在规定长度档的基线能力、路径分类、静态精度敏感度与页访问数据；
- 包含 packing 浪费、元数据扫描、选页、反量化、写回和停顿的有效带宽与能量模型；
- 区分同一步沿上下文归约的数值误差、跨层误差和跨生成步误差。通过算子参考、固定输入轨迹与实际自回归任务分别验证；不以长输入评测代替长生成稳定性，也不要求核心阶段连续生成 $10^5$ token。

### 4.2 架构（对应 $\pi, b$ 的硬件实现）

- 一个支持 **规则流式路径 + 有界检索路径** 的 Attention/KV 引擎，包含读取、选择、追加写入和元数据维护；
- 与 INT4/INT8 静态配置一致的存储格式、标签及融合反量化计算流水；
- 核心引擎可综合 RTL、参考模型对照、面积/功耗估计/时序结果及性能模型校准记录。RTL 须覆盖声明收益所依赖的核心机制，不能仅用一个 MAC 模块综合值代表完整引擎；
- 任务质量可由与硬件语义一致的软件实现评测，不要求全模型逐周期 RTL 仿真；软件与 RTL 在代表性数值、边界页和缓存更新用例上建立对应。

### 4.3 映射方法（对应 $\mathcal{M}$）

- 输入：模型结构、分离的校准数据或其统计、上下文/访问预算、任务质量约束、硬件预算；不能只凭结构推定质量可行域；
- 输出：KV head 组分派、静态精度、页组织、tile/bank 绑定及流水调度；
- 形式：可复现的搜索或启发式工具，附可行域、Pareto 曲线，以及同等搜索预算下“分步优化后组合”与“联合优化”的比较。

### 4.4 明确不作为交付物

- 新的 LLM 算法层面的“更好 KV 压缩方法”（若为达成硬件目标顺带产生，仅作辅助结果）；
- 完整推理系统或服务框架；
- 通用 Transformer 加速器（须能支持所有算子并对比全模型端到端）。

### 4.5 完成与贡献成立的区别

上述交付物完成意味着证据链完整。若联合方案没有超出对照的质量–能量–延迟取舍，应报告负结果并重新审视机制；不得仅凭完成双路径 RTL 就宣称研究假设成立。宣称改进时须说明适用工作负载、代价和测量/建模不确定性，不预先承诺任意加速倍数。

## 5. 评测边界

### 5.1 必须报告

| 类别 | 指标 |
|---|---|
| 质量 | RULER 等可控长度任务覆盖核心档位，并包含检索与非单针检索任务；LongBench 等真实任务补充。登记版本、任务子集、实际长度及评分；短文本 PPL 只作补充 |
| 传输与容量 | 每生成 token 的片外实际传输字节；KV/元数据驻留容量；有效载荷与总传输量；可达上下文长度分别受质量、容量和延迟何种条件限制 |
| 能量与延迟 | Attention 引擎及存储的 J/token、每步 Attention 服务时间、完整模型 TPOT 的实测或估算及其构成；每项标注来源和边界 |
| 电路 | 面积、功耗估计、时钟频率、SRAM 端口冲突、片外突发利用率、选择器与流水停顿统计 |
| 消融 | 分步组合 vs 联合搜索；均匀精度 vs 混合精度；去流式结构；融合 vs 独立反量化；选页和元数据成本；可用模型比较页级访问与任意 gather，无需为后者新增 RTL |

“Bytes/token”定义为测量区间内全部相关片外读写字节除以实际新生成 token 总数，包含 KV、scale/zero-point、标签、索引、页统计、对齐/尾页浪费和写回；片上访问另报。batch 大于 1 时分母是各序列生成量之和；同步批处理的总吞吐 $B/T_{\mathrm{step}}$ 与单请求 TPOT 分开报告。

主能量边界为全部模型层的 Attention/KV 引擎逻辑、片上存储和相关片外访问，按新生成 token 归一化。主时间预算覆盖同一范围的 Attention 服务时间；QKV/输出投影、FFN 等单独建模后才能得到完整 TPOT。每个实验表明主机交互、共享内存竞争及初始化是否包含，组件结果不得直接冠以整机结果。

质量基线固定模型权重、权重/激活精度、位置编码与生成设置，仅对 KV/Attention 策略进行对比。$\Delta q$ 为按任务规则统一到 0–100 分后，基线分数减候选分数的**绝对分数差**；低值更优的指标另定有方向的容差。每个必测模型、任务/任务组和长度档均有冻结的容差，禁止以总体平均掩盖检索失败。

同时冻结高精度基线的最低能力要求、样本数、随机种子与重复/置信区间方案；精度容差不能在查看测试结果后调整。校准/搜索不得使用最终测试答案或逐样本最优配置。基准名称不代表长度覆盖，真实任务结果与合成长输入结果分别呈现。

### 5.2 必须比较的基线

- 全量 FP16/BF16 KV，以及均匀 INT4/INT8 KV；
- 纯流式（StreamingLLM 类）与 head 混合（DuoAttention 类）；
- 至少一种直接接近的 page 选择方案（LServe 或 Quest），并优先采用能覆盖所提机制的配置；
- 本课题同一硬件模板上的分步组合方案：固定稀疏后选精度与固定精度后选稀疏两种顺序，再映射硬件；报告相同搜索预算和质量约束；
- 至少一个最接近的已发表硬件方案的对齐模型，依据最终机制从 Oaken、AccLLM、FlightLLM 等选择并说明理由；SnapStream、LAD、SOFA 等进入机制对照，若其覆盖最终主张则升级为定量对照。

算法质量、同模板机制收益、跨平台效率分别比较。GPU 结果注明设备、软件、batch、长度和数值格式；ASIC 模型不能与 GPU 整卡测量直接作无边界说明的能效比。硬件前作无法完全复现时，登记重建假设及范围，不用推测值冒充原论文实测。某基线未满足质量约束时，保留其失败结果，不以其低成本作为保质收益证据。

### 5.3 不要求

- 与商用 GPU 在绝对吞吐上取胜；核心论点以对齐条件下的任务质量、实际流量、能量与延迟取舍为准；
- 覆盖全部开源模型或全部参数笛卡尔积。核心完整矩阵为“两款模型 × 三个长度档 × $B=1$”；质量按任务协议生成，效率按第 2.4 节测量。$B=4$ 的补充 trace/模型验证只需代表配置；有条件扩展也可选代表配置，均须说明选择原则；
- LongBench 中每个样本达到 128K、所有基线都有定制 RTL，或完整模型全部在 FPGA 上运行。

## 6. 配置冻结、依赖与验收

### 6.1 正式实验前冻结

当前仓库未提供目标工艺、工具许可、板卡或模型运行资源的确认材料。下列项目是待确认配置，不得写成已有实验条件。可行性试验完成后，将完整设置记录在仓库内的实验协议中，正式测试使用同一版本：

- 两款模型的 checkpoint/修订号、权重与激活格式、位置编码、核心长度档的基线能力；
- 任务版本、长度统计、生成设置、校准/测试划分、各项 $\epsilon_{t,S}$、基线能力下限与统计方案；
- sink/窗口长度、KV head 组分类方法、INT4/INT8 量化细节，以及第 2.7 节全部预算和有限搜索集合；
- 工艺库、综合工具/版本、PVT/时序约束、SRAM 宏或有来源的存储模型、面积/容量/时钟预算；
- 片外接口的通道、容量、突发和可持续带宽参数、能量来源、Attention 延迟预算、系统边界与建模假设；
- 基线版本、资源对齐规则、搜索预算、性能模型校准用例和可接受误差阈值。

不得在测试后放宽质量或资源预算来保留有利结果；协议变更须记录理由并重跑受影响的对照。

### 6.2 依赖缺失时的处理

| 缺失条件 | 允许的处理 | 对完成标准的影响 |
|---|---|---|
| HBM FPGA 板卡 | 保留 RTL 验证与有来源的存储模型，说明缺少板级实测 | 不影响核心完成；不得宣称获得实测带宽 |
| 70B、256K 或 MLA 运行资源 | 省略对应扩展，或仅作明确标记的形状/容量分析 | 不影响核心完成 |
| 工艺库、综合工具或可信 SRAM 参数 | 可先做功能与性能探索；更换合法可用的库/工具并重定预算，或正式修订交付路线 | 仅有性能模型不能满足当前电路验收要求 |
| 两款核心模型的质量评测资源 | 更换满足同一边界的模型或分阶段运行；若仍无法完成则修订核心矩阵 | 容量/周期模型不能替代任务质量证据 |
| 目标 prefill 格式或接口 | 实现并核算转换与元数据构建；以软件参考验证语义 | 不得隐藏转换代价或跳过格式兼容验证 |

### 6.3 分阶段验收

1. **可行性与配置冻结**：确认资源、两款高精度基线能力、核心机制假设和最接近前作；形成可复现协议。
2. **软件与数值验证**：完成核心质量矩阵及关键消融，确认预算内存在可行策略；失败则调整假设并记录原因，避免直接扩大 RTL 范围。
3. **硬件与模型验证**：完成核心 RTL、综合/功耗估计/时序、覆盖选页与更新的功能检查及性能模型校准。
4. **贡献验证**：在冻结约束下完成分步组合与联合方案比较，报告 Pareto 取舍、局限、搜索成本和证据类型。

达到阶段 4 才具备核心交付的完整证据；FPGA 与其他扩展按资源追加，不回写成所有阶段的必需条件。

## 8. 与既有工作的关系及待验证分界

文献身份与阅读入口统一见 [文献清单](literature-survey-reading-list.md)。下述已有机制不作为本课题的新颖性主张：

- StreamingLLM、DuoAttention 提供流式及 retrieval/streaming head 策略；[LServe](https://arxiv.org/html/2502.14866v2) 已结合静态/动态稀疏、KV 量化与 GPU 实现，并讨论页粒度对精度与效率的影响。不能将其概括为只有算法模式。
- [Quest](https://proceedings.mlr.press/v235/tang24l.html) 的 query-aware page min/max 选择作为核心候选方法来源；采用该选择器本身不构成新贡献。
- KIVI、KVQuant、KVTuner、QServe 等分别提供 KV 量化、精度分配或执行优化依据；量化异构的粒度和机制需逐篇区分，不能统一归为同一种混合精度。
- FlightLLM、Oaken、LAD 等覆盖映射、KV 量化硬件与局部性；[AccLLM](https://arxiv.org/abs/2505.03745) 已结合剪枝、Λ 形 Attention、低比特 KV 与 FPGA 设计；[SnapStream](https://arxiv.org/abs/2511.03092) 已展示数据流加速器上的稀疏 KV 部署。需与这些机制逐项比较。

**拟验证的分界**：在 GQA 长上下文 decode 的质量约束下，针对低比特 KV 页的传输利用率、选择开销及共享访问冲突，提出具体的数字电路机制，并证明其与有限策略/映射联合搜索的收益超出同资源、同质量、同等搜索预算下的分步组合。

分界成立须同时给出最接近前作的机制对照、关键硬件消融及分步/联合优化结果。若前作已覆盖所提机制，或收益不能在完整成本下成立，应更新研究假设，不能仅以平台不同或模块名称不同作创新依据。
