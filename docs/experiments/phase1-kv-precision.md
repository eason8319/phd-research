# 第一阶段实验计划：A 类 KV 表示机制的适用边界与读出成本

修订日期：2026-09-22。本轮依据 [A 类精读](../section-readings/a-section-reading.md) 与 [项目范围](../project-scope.md) 设计，文献身份统一使用 [文献清单](../literature-survey-reading-list.md) 的 A01–A10。本轮尚未运行；下文的样本量、容差、搜索上限均为拟定实验设置，不是已有结果。

本计划是项目第 1 阶段中 **A 类机制的可行性与证据准备子计划**。完成本计划不等于完成整个项目的配置冻结。输出是少量可继续验证的配置、解释成功与失败的证据，以及交给后续访问策略和硬件实验的约束。

## 1. 实验边界与项目目的

### 1.1 本轮研究什么

本轮只改变 A 类论文涉及的 KV 表示：量化轴、K/V 位宽、scale 来源与位宽、分组、RoPE 顺序、近期高精度残留，以及层静态精度分配；测量这些表示的数值误差、存储、追加写入和读出成本。

所有任务质量实验保持 **全历史 dense Attention**，不驱逐 token、不按重要性选择历史页。任务中的“检索”指模型完成长距离信息检索题，不表示启用了 retrieval 路径或页选择器。

| 本轮对象 | 处理方式 |
|---|---|
| 主候选 | 现成 GQA 模型；均匀 INT4/INT8、K/V 不对称、layer × K/V 静态位宽；历史元素的位宽不随 decode 改变 |
| A 类诊断对照 | 分组完成前的高精度缓冲、近期 INT8/FP16 残留、静态逐 token 标签的布局回放；每项显式核算，不能自动成为主候选 |
| 格式与读出模型 | 固定物理打包块、突发对齐、scale 读取、反量化、RoPE、两段矩阵运算和依赖关系；用于核算已有表示，不开发新架构 |
| 暂不开展 | streaming/retrieval head 分类、路径分派、sink/窗口驱逐、page min/max 评分与 top-k、稀疏访问预算搜索、RTL、bank/PE 映射优化 |
| 不作为本轮必做 | INT2、非均匀码本、稀疏异常值支路、GEAR 低秩重建、MiniCache 跨层合并、TurboQuant 的完整量化器、GTA/GLA 结构转换 |

GQA 共享关系直接从 checkpoint 读取。误差可以细分到 query head，但存储与传输按 KV head 计数，不把共享消费者数重复计入压缩收益。A 类中的 head 敏感性观察只用于解释层内差异，本轮不给 head 命名或分派访问路径。

### 1.2 为什么这些实验对整个项目有用

项目最终研究的是质量约束下的精度、页组织、访问与硬件映射。本轮先回答其中四个会改变后续设计的问题：

| 待检验问题 | A 类依据 | 本轮要得到的证据 | 后续项目决策 |
|---|---|---|---|
| H1：Key 优先升位宽的收益是否依赖量化轴、RoPE 和 scale 来源？ | KIVI（A02）、KVQuant（A04）、KVTuner（A08） | K8V4/K4V8 的优劣是否换序；误差发生在重建、logit 还是输出 | 精度搜索是否必须与表示格式绑定，是否需要两种 K/V 格式 |
| H2：无高精度历史缓冲的静态表示，在哪些条件下足以保持质量？ | KIVI（A02）、SKVQ（A03）、KVQuant（A04） | 离线 scale 漂移、组闭合误差与近期残留收益的分离 | 固定页格式能否成立；是否存在不可忽略的追加、缓冲或高精度通路要求 |
| H3：短校准得到的层敏感度，能否指导长上下文中的静态分配？ | KVTuner（A08）；误差诊断参考 A02/A10 | 层排序的迁移性、累计误差和同预算随机对照 | 后续映射可使用何种校准信息，静态配置能否跨工作负载复用 |
| H4：质量合格的低位宽表示，何时真正降低传输和服务时间？ | A02/A04 的读出、A03/A05 的元数据、A09 的算术强度视角 | 实际字节排序与名义位宽排序是否不同；收益的带宽/读出吞吐边界 | 给硬件阶段提供格式候选、吞吐要求和失效条件 |

这些是本课题工作点上的待检验假设。复现前作趋势、发现趋势不迁移、或证明复杂方案收益不足，均为有效结果；仅采用既有机制不构成创新。

## 2. 共用设置与判定规则

### 2.1 模型、长度与参考语义

第一对候选为 **Llama-3.1-8B-Instruct** 与 **Qwen2.5-7B-Instruct**。选择依据是跨模型检验，而非预设后一款一定在 KV4 下失败。KVTuner 的模型敏感性结果提供动机，具体表现须在本轮格式下重测。[A08 原文](https://proceedings.mlr.press/v267/li25dd.html)

开跑前登记 checkpoint/修订号、层数、query/KV head 数、head dimension、位置编码、权重与激活格式、框架版本、Attention 实现与生成设置。模型替换按项目范围第 7 节记录，不能为得到预期失效或成功而临时换模型。

- 质量：短上下文用于诊断，32K 用于迁移与可行性；1K = 1024 token。32K 档记录实际输入、输出与总长度，不让生成超过已验证窗口。
- 效率：B = 1 为本轮必做；4K、32K、128K 做字节与读出模型。128K 的合成形状不提供该长度的质量证据。B = 4 仅在主要候选形成后选一个代表配置补充。
- 基线：同权重、同位置编码的全量 BF16/FP16 KV、均匀 KV8、均匀 KV4。比较某一因素时其余数值与缓存规则相同。
- 固定 score、softmax、累加和输出格式，先验证参考误差，不把其改变混入 KV 量化收益。
- 主任务参考的 prefill 使用高精度计算，在约定接口处构建目标格式；decode 读取该格式并量化新 KV。若增加“prefill 内也使用量化 KV”的校准方式，单列为另一实验条件，不替换主协议。
- 每个模型、任务组、长度档先检查高精度基线能力。能力下限须在候选比较前登记；基线不成立时，该单元不能提供量化保真结论，也不能只挑基线答对的题重算主分数。

### 2.2 把表示规则写成可执行规格

“静态”分别说明位宽、scale、存储成员，不用一个词替代三项规定。

| 表示 | scale 与追加规则 | 本轮身份 |
|---|---|---|
| Key 离线 per-channel | 每层、每 KV head、每通道的 scale/零点由校准集确定，decode 固定；新 token 立即量化 | 主候选，记录超界与饱和 |
| 在线 per-token 分组 | 每个 token 沿通道分组，参数由该 token 计算；旧 token 的参数不变 | 主候选，K/V 均可作对照 |
| Key 在线跨 token 分组 | 同一通道的 G_t 个 token 闭合后计算参数；闭合前的数据如何参与 Attention 必须明确 | 默认诊断对照；依赖 FP 历史缓冲时，不标成无残留主候选 |
| 近期高精度残留 | 新旧表示如何共存、何时淘汰高精度副本或转换，逐项登记 | 只用于 H2 的受控诊断 |

跨 token 组长记为 G_t，单 token 内的通道组长记为 G_c，避免用一个 G 混淆两种轴。离线逐通道 scale 没有“等 G_t 个 token 才能定 scale”的要求。物理打包仍可按块进行，但不能据此推导所有格式都需要同样的 token 页长。

每个配置还须登记：对称/非对称、量化公式、整数码范围、scale/零点的实际存储类型、舍入、裁剪、饱和、零动态范围处理、FP8 scale 的下溢/溢出规则、RoPE 顺序及尾块策略。不能把浮点偏移量与整数零点的字节数混用。

未满组缓冲只要以 FP16/BF16 参与 Attention，就具有高精度残留效应，必须核算其质量、容量和读取成本；不得仅因用途是对齐而忽略。当前步必须能读取所有可见 KV，不能等待未来 token 填满组才完成当前步。任何在线参数计算都不能使用尚未生成的 token。

KIVI 的组缓冲与 KVQuant 的离线通道 scale 是不同方案；借用其中一个机制不等于复现整篇方法。[A02 §3.3](https://arxiv.org/html/2402.02750v2)、[A04 §3.6](https://proceedings.neurips.cc/paper_files/paper/2024/file/028fcbcf85435d39a40c4d61b42c99a4-Paper-Conference.pdf)

### 2.3 数据划分、样本预算与不确定性

本轮使用校准集 C 与开发验证集 V；第二阶段最终测试集 T 独立保留。C 用于 scale、层排序和配置搜索；V 用于本轮迁移检查与候选取舍，故 V 的结果仍是开发证据，不能冒充最终测试。

下表为起始预算。运行资源未确认时先登记可执行版本，再采集结果；不得在看过结果后无记录地缩样本或放宽标准。

| 数据 | 起始设置 | 用途 |
|---|---|---|
| C：短困难生成 | GSM8K 训练划分中预先固定的 64 个样本，登记提示与示例来源 | scale 校准、层敏感度、生成误差诊断 |
| C：检索探针 | 32 个独立合成样本，覆盖预登记的短长度与证据位置 | 检查仅靠数学题校准是否偏向某类误差 |
| V：短困难生成 | 与 C、T 不重叠的 64 个样本 | 先确认短任务迁移与真实 decode |
| V：32K 检索 | 64 个样本，覆盖至少 4 个证据深度与 2 档干扰条件，生成种子与 C/T 分离 | 检查远处信息的量化失效 |
| V：32K 困难生成 | 64 个现有长文问答或多证据推理任务样本；开跑前冻结任务、版本和评分 | 检查长输入与多步生成同时出现时的质量 |

32K 困难生成必须实际使用远距离材料，不能仅把 GSM8K 填充到 32K。样本或任务若无法满足长度与基线能力要求，应报告缺口并调整预登记协议，不把短生成结果改名为长上下文验证。小规模固定输入轨迹从这些样本中预先选取，不另挑“效果最明显”的个例代表总体。

质量分数统一到 0–100，下降定义为基线减候选的绝对分数差。**本轮保留 2 分作为开发筛选容差**，同时报告相对高精度与 KV8 的结果；主候选不能只因接近已经退化的 KV8 而过线。此容差不是第二阶段正式的 $\epsilon_{t,S}$。

对相同样本做配对分析。开跑前冻结区间计算方法：二值任务使用适合配对比例差的区间，连续分数使用样本级配对重采样；同一样本的多个 token 不作为独立样本。报告样本数、分歧题数、分项分数和区间，不只报均值。全无分歧时也不能用退化的重采样区间声称已证明非劣。

- **保留候选**：相对两种参考的下降区间上界均不超过 2 分，且没有被分项结果暴露的系统性失效。
- **淘汰当前配置**：下降区间下界已超过容差，或存在经定位的实现/格式不可行；结论只针对该配置，不推广到整个机制。
- **证据不足**：区间跨越容差。只对少量最终候选按预登记顺序扩至 128、最多 256 个样本；仍不明确则保持此状态。

分层结果以诊断为主；若位置、任务子组样本不足以判断，写“证据不足”。本轮筛选涉及多配置比较，区间用于开发决策，不提供最终非劣性证明。完整统计方案和各任务正式容差留待第二阶段冻结。

### 2.4 三本账与三种证据

1. **驻留容量**：KV 载荷、scale/零点、标签、padding、缓冲及对照中的重复副本；注明峰值与稳态。
2. **片外传输**：实际读写事件及其载荷/元数据/对齐分解；按测量区间内新生成 token 数归一化。读写是方向，元素/参数是内容，不能把同一笔写入算两次。
3. **片上访问**：缓冲、解包、反量化中间量和参数缓存的访问及容量，单独报告，不直接加进片外 bytes/token。

名义位宽按实际元素数加权；容量有效位宽与传输 bytes/token 分列。离线 scale 的容量占比随历史变长可以下降，但其读取流量取决于缓存与重用，不能由容量比例代替。

当前没有页选择器，因此选择元数据记为“本轮未实现/未包含”，本轮结果标为 **dense KV 表示及读出边界**，不能称为最终引擎总字节或总能量。prefill 转换和参数构建一次性开销单列，摊销时写明生成长度。

每项结果标注：软件任务/算子实测、按确定布局计数、或带假设的性能模型。假量化可以验证数值，不能证明实际压缩流量或加速。

## 3. 实验内容

### E0：参考正确性与格式账本

**目的。** 排除实现差异造成的假现象，为 H1–H4 建立可追溯输入。

先在合成边界值和少量真实 KV 上检查：量化—打包—解包—反量化一致；pre/post-RoPE 的全精度对照一致；因果可见性与追加语义正确；KV8、KV4、K8V4、K4V8 的数据布局可计数。覆盖常量组、超界值、未满组、刚闭合组、整块与尾块。

对每个格式建立“元素/参数/标签/对齐 × 读/写”的记录。手算一个小张量，并与实现或事务回放逐项核对。FP scale 在哪里驻留、何时重复加载必须可追溯。

**完成标准。** 给出参考误差、格式规格与三本账样例。若只有假量化实现，明确哪些布局成本来自模型；先解决正确性问题，再比较量化质量。E0 不要求实现尚未进入范围的页统计或选择器。

### E1：K/V 精度优先级与表示方式的交互

**假设。** “Key 比 Value 更值得增加位宽”可能依赖轴、RoPE 与 scale 来源；重建 MSE 最小也未必产生最小的 Attention 输出误差。

**主对照。** 在相同高精度输入轨迹上固定 query、历史 K/V 和可见长度，只改变当前层的表示，隔离跨层反馈。Value 起始用 per-token、G_c = 32、FP16 参数；Key 使用下表两种轴。主矩阵最多 16 个算子条件，不把每个条件都扩为全模型任务。

| 因素 | 主矩阵取值 |
|---|---|
| Key 表示 | 离线 per-channel；在线 per-token、G_c = 32 |
| RoPE 顺序 | pre-RoPE；post-RoPE |
| 位宽对 | KV8、K8V4、K4V8、KV4 |

追加对照只围绕主矩阵暴露的差异，每款模型的 E1 算子条件总数上限为 32：在线跨 token Key 组的 G_t = 32/64/128；Value 的 per-channel 对照；G_c = 64/128；FP16 与 FP8(E4M3) 参数。追加顺序、目的和预算开跑前登记，不能全部交叉展开。跨 token 组的全模型行为交给 E2；只测已闭合组的结果不能替代真实追加验证。

pre-RoPE 与 post-RoPE 分别校准相应空间的参数，使用同一批 C 数据与同一预算。不能让某一种表示额外使用长验证集校准。K4V8 与组长 128 均作为正常候选或反例，不预先指定为淘汰项。主矩阵比较的是完整表示组合；轴与参数来源同时变化的差异不能全部归因于轴，参数来源的定位在 E2 补做。

**测什么。**

- K/V 重建误差、饱和率与参数范围；区分平均误差和高误差尾部。
- 缩放后 logit 误差、Attention 概率差异、输出向量相对误差；按层和 KV 共享组统计中位数及高分位数。
- 对 logit 误差同时报告原始均值与去掉当前 query 全 token 公共偏移后的误差。softmax 对公共平移不敏感，不能把公共偏移直接解释为质量损伤。
- 检查重建 MSE、输出误差对配置排序是否一致，记录换序的具体层、输入和表示条件。近零分母的相对误差使用由 C 冻结的稳定规则，不能仅凭“误差高一个数量级”淘汰整个轴。

A10 在这里提供“重建误差与内积误差应分开观察”的诊断动机；本轮不实现新的去偏量化器，也不假定均匀 INT4 必然具有原论文量化器的同一种偏差。

**判定与输出。** 若 K8V4 在不同表示下始终占优，记录其适用范围；若发生换序，给出相同输入下的反例及元数据差别。每款模型保留至多两种有不同质量—成本优势的非基线表示进入 E2。局部误差只负责排序与诊断，最终采用仍依赖全模型任务。

**项目用途。** 决定后续精度搜索能否只搜位宽，或必须把轴/scale/RoPE 一起作为配置。两款模型可以选择不同表示。

### E2：静态 scale、近期缓冲与误差累积的来源

**假设。** 某些低位宽配置的失败可能来自离线范围失配、近期表示精度或跨层/跨生成步反馈，而非名义位宽本身。找出原因后，才能判断是否需要更复杂的存储与读取支持。

主比较为高精度、KV8、KV4，以及 E1 留下的至多两种表示。先跑 C 的真实 decode 和 V 的短任务，再对候选跑 32K；严重失效配置保留记录，不强行完成其全部后续组合。

**第一组：离线 scale 能否迁移。** 离线参数只由 C 得到，在 V 上冻结；按历史位置、生成阶段和层记录超界率、饱和误差、输出误差及任务质量。对少量固定快照，另用当时可见的高精度历史计算 per-channel 参数，保持位宽、轴、RoPE 与范围估计规则一致，用于判断重新估计范围能否解释误差。这是借助高精度参考的诊断，实际部署可能需要重编码历史，不能当作免费在线方案，也不能用它更新冻结候选。

再比较 E1 留下的在线闭合组格式，分别记录组粒度与缓冲效应。整通道离线参数和局部分组在线参数同时改变了统计范围，二者的质量差不能全部归因于“离线/在线”。所有上述诊断均不允许用 V 重新校准后宣称迁移成功。

**第二组：近期高精度到底修复什么。** 对一个预先选定的无残留低位宽主干，使用近期长度 R = 128、残留精度 H = 0/8/16 的受控对照；H = 0 表示无残留，H = 8/16 分别表示 INT8/FP16。主干从写入时即保持固定表示，H > 0 另留近期副本并在离窗后丢弃，读取时以近期副本替代相同 token 的主干值。INT8 副本沿用主干的轴与范围估计方式，仅改变位宽；记录实际参数。该设计隔离近期精度作用，不宣称完整复现 KIVI。

三臂保持主干 scale、RoPE 和位宽一致。分别计入重复存储、双份追加、选择读取与尾部处理。默认每款模型仅对一个主干做这组诊断；如无质量差异，不继续搜 R。H = 8/16 都不是无残留主候选，不能以“不改旧主干位宽”为由把第二份表示的成本隐藏起来。

另对 E1 的一个在线跨 token 分组格式记录组内位置 r = 当前 token 数 mod G_t 对误差与写入的影响；将闭合前后跳变与近期残留的平滑收益区分。若生成轨迹很短、没有跨过组边界，不足以判断组闭合机制。

**第三组：误差在哪一层开始影响生成。** 对少量预登记轨迹比较：

1. E1 的单层隔离误差；
2. 固定同一 token 序列、全层使用目标 KV 格式的逐步回放，观察跨层累计而不让输出 token 分歧改变输入；
3. 实际自回归生成，观察首次输出分歧、最终任务分数及生成长度。

固定输入回放不能替代任务质量。发生自由生成分歧后，两条序列对应的隐藏状态不同，不继续把其差值当成相同输入下的纯量化误差。

**判定与输出。** 分开写“无残留静态格式可行”“依赖近期副本或组缓冲”“离线 scale 在当前校准下失配”“局部误差不足以解释累计失败”。各结论附分项质量与不确定性，不把诊断性改善直接变成采用判决。

**项目用途。** 给出固定历史格式是否足够的证据；若只有有条件对照可行，列出额外容量、数值通路和更新语义，再按项目范围决定后续是否纳入。不能把高精度需求改名为对齐需求。

### E3：层敏感度的迁移性与静态分配的实际价值

**假设。** 层敏感度若在校准划分之间稳定，且在相同成本下优于无信息分配，才适合充当整个项目的离线映射输入。均匀 KV4 失败不是启动该实验的前提。

固定 E2 中一种可解释的表示，层内候选为 E1 未被排除的 KV8、K8V4、K4V8、KV4。先对 C 中的数学与检索子集分别计算层敏感度：一次降低一层或将一层恢复高档，记录输出误差和固定轨迹上的预测损失变化。每次干预明确其全网背景配置，不能把全网 KV8 背景下的排序当作 KV4 背景下已经成立。

用预登记的简单排序/贪心方案分配高档，报告搜索预算，不在本轮开发新的通用精度搜索算法。选择两个由可实现成本范围预先确定的预算点，比较：

| 对照 | 要回答的问题 |
|---|---|
| 按 Attention 输出敏感度分配 | 所测敏感度是否有预测价值 |
| 按重建 MSE 分配 | 便宜的重建指标是否已经足够 |
| 高低档层位置随机置换，固定 3 个种子 | 收益是否仅来自增加了同样多的高精度数据 |
| 将高档优先分给低敏感层 | 作为层排序失效或反向的诊断 |
| 均匀 KV8/KV4、全网 K8V4/K4V8 中适用者 | 静态层混合是否值得增加格式配置 |

每个预算点最多评估 8 个层分配，先在 C 上筛选；相同格式的均匀/全网基线复用已有结果。分配间保持各精度档的元素总数与格式规则可比，按完整 KV 字节核查；层形状不同时按实际元素数加权，不能仅匹配高档层数。离散配置不能精确对齐时，用同一成本上限比较并报告实际差额，不通过无意义填充伪造等成本。

为控制任务运行量，开跑前指定其中一个主预算点。将该点选出的至多两个非随机分配，以及 3 个固定种子的匹配随机分配一同冻结，进入 V 的短任务与 32K 任务；不能只让最优方案验证迁移、把随机对照留在 C。另一预算点先用于 C 的成本取舍与固定轨迹诊断，不声称已验证其任务迁移。

同时报告 C 的两个子集之间、C 与 V 之间的层排序相关、敏感层集合重合和完整配置质量。V 的层排序使用预登记的小型轨迹子集，注明其样本量；它只用于解释迁移，不回流修改本轮冻结配置。不同预算点中没有达到质量条件的方案保留为失败点。

**判定与输出。** 层排序一致但整体质量失败，说明局部排序不充分；排序改变但任务质量稳定，说明排序差异未必需要更细粒度。若敏感度分配与等成本随机分配相当，应记录静态层混合的收益证据不足，保留较简单的候选。

可以附报同层 KV 共享组的误差离散度，用于判断层级指标是否掩盖少数异常组；不据此在本轮开展 head 分类、独立 head 位宽或路径配置。

**项目用途。** 交付可迁移的层配置或其失效边界，为后续联合搜索提供输入。这里的“优于随机/均匀”不等于已经证明优于整个项目的分步优化基线。

### E4：同等质量下，表示成本何时改变优劣顺序

**假设。** 按名义位宽、驻留容量、实际传输和服务时间排序，可能得到不同的候选。需要测出换序条件，而不是仅确认“元数据有开销”。

E0 的计数器提前用于 E1–E3 的预算；本项在质量候选形成后完成。主任务成本来自全历史读取，测量区间原则上采用连续 256 个 decode 步并记录实际长度。固定步数的效率回放与按任务协议停止的质量分开，不延长或截断答案来凑效率区间。

**对照 A：同样元素位宽，改变参数组织。** 对 INT4 或 E2 留下的位宽，比较离线通道参数、在线组参数，以及候选支持的 FP16/FP8 参数。容量与流量分别计数。较少参数的格式如果质量不合格，只能作为失败点，不能据此宣称有效收益。

**对照 B：同样精度比例，改变布局粒度。** 从一个既定位宽直方图构造按层连续布局与静态逐 token 标签布局，在合成回放中保持高低档元素数量相同，只比较标签、padding、寻址和解包。这是受 A05 启发的格式对照，不运行 token 显著性算法，也不把换过精度位置的张量当作同质量结果。

INT4/INT8 混合的名义位宽为：

$$
\bar b = 4(1-p)+8p=4+4p.
$$

非零 INT8 占比不能与纯 INT4 匹配名义位宽。名义位宽相等也不意味着总传输相等，后者正是本项测量对象。

**对照 C：表示的读出代价。** 对 KV8、K8V4、K4V8、KV4 中已有可用实现或模型的条件，记录 K/V 各自的载荷与参数字节、反量化吞吐、RoPE 运算、QK、softmax、AV 和中间缓冲。比较融合读出与先反量化再乘的参考流程，明确中间量落在片上还是片外。

若只计低比特载荷、每份 KV 对组内 query 被完整复用，单段的理想算术强度为：

$$
I_{\mathrm{payload}} = \frac{16g_q}{b}\ \mathrm{FLOP/byte},\qquad g_q=h_q/h_{kv}.
$$

这是本计划按一次 MAC = 2 FLOP 推导的载荷上限口径。实际强度按实际传输重算；重复加载、参数和对齐会降低它，不能把 GQA 的理论复用当作已实现的带宽收益。

设 K/V 的实际读取字节为 D_K、D_V。共享通道与独立端口的内存时间下界分别为：

$$
T_{\mathrm{shared,lb}}=\frac{D_K+D_V}{W},\qquad
T_{\mathrm{split,lb}}=\max\left(\frac{D_K}{W_K},\frac{D_V}{W_V}\right).
$$

主比较保持总带宽相同，即 W_K+W_V=W；增加总带宽的情形另列资源敏感性。上述公式只描述内存下界，完整服务时间还需满足 QK → softmax → AV 的依赖、预取缓冲和读出吞吐约束。以串行参考与明确可重叠的调度模型给出范围，不把两个端口自动等同于完全重叠。

融合反量化可以减少中间访问，但其吞吐、流水延迟、参数供给和资源成本都要登记；没有测量或实现依据时不填写“零额外开销”。本轮不由 GPU kernel 时间推断 ASIC 延迟或功耗。

**有限成本扫描。** 物理打包块先取 32/64/128 token 的有限集合，对齐粒度来自登记的接口假设；跨 token 分组只使用能容纳完整组的组合，尾块单独计数。这里的块不参与选页，也不决定最终逻辑页长。未确定真实带宽、时钟或单元吞吐时，使用明确的低/中/高假设，输出候选排序改变的阈值，不给伪精确硬件预测。

可追加固定读取长度 N_read 的合成扫描，观察小读量下反量化是否抵消压缩收益；它仅为后续稀疏/流式实验提供成本函数，不改变本轮任务的可见历史，也不证明任何读取子集能够保质。

**判定与输出。** 在相同质量条件下，以驻留容量、bytes/token 和服务时间模型形成候选前沿；单独列出不可比或证据不足点。若能源单价/活动率没有可信依据，只报告访问与操作计数，不把字节节省写成 J/token 节省。已有来源时可附参数化能量估计，并注明缺失组件。

**项目用途。** 输出格式所需的最低读出吞吐、缓冲需求、带宽适用区间及物理块候选，后续再加入选择器、路径与真实电路成本。

## 4. 执行顺序、预算与停止条件

先登记可用运行资源、数据版本、样本清单、生成协议、量化规格、误差定义、区间方法及每项预算，再按下列顺序执行。需要修改协议时版本化记录，并重跑受影响的对照。

| 顺序 | 必做内容 | 控制工作量的方法 |
|---|---|---|
| 1 | E0 与两款高精度基线能力检查 | 少量样本排查实现；不凭少量样本认定质量通过 |
| 2 | E1 局部机制与关键交互 | 每模型最多 32 个算子条件，最多两种非基线表示晋级 |
| 3 | E2 真实 decode、32K 迁移和必要诊断 | 基线加至多两种候选；每模型一个主干做残留诊断，一个格式做组闭合诊断 |
| 4 | E3 静态层分配 | C 上两个预算点，每点最多 8 个层分配；一个主预算点的至多两个候选及 3 个随机对照进入 V |
| 5 | E4 成本前沿与阈值 | 对少量存活候选及必要失败对照展开，避免模型 × 所有格式 × 所有硬件假设全组合 |

实现或高精度基线不成立时先定位原因；没有主候选通过时，记录失败条件和额外需求，不自动扩展到 INT2、训练或更多模型。对同一现象的定位最多追加一组能区分原因的对照；超出预算的线索登记到后续 backlog。

本轮不要求四个假设都出现“有利发现”。若只有均匀 KV8 稳定，或静态层分配没有超过简单方案，仍可交付负结果与成本记录。尚未运行、因资源省略、以及已证伪必须分别标注。

### 5.2 对整个项目的价值与保留问题

| 本轮发现 | 能支持的下一步 | 本轮不能直接断言 |
|---|---|---|
| 位宽优先级随轴或 RoPE 改变 | 后续联合搜索保留少量“表示＋位宽”候选 | 已证明联合精度、稀疏与映射优于分步组合 |
| 离线 scale 或层配置跨任务迁移失败 | 调整后续校准覆盖与映射输入，保留失败案例 | 必须改为运行时动态精度 |
| 近期高精度或组缓冲作用显著 | 明确追加通路和缓存状态的代价，评估是否纳入有条件实现 | 用某条 streaming 路径就能替代残留 |
| 同层组误差分化明显 | 给后续 head 路径实验提供待验证对象 | 已识别 retrieval/streaming head |
